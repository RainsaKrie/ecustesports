# Esports Operations Assistant
> **状态以 [`docs/00-项目管理/当前主线.md`](docs/00-项目管理/当前主线.md) 为准**（2026-10-19 起）。
> 本文中凡涉及「当前阶段 / 测试套件数 / 赛制 / Gate 进度」的表述一律视为历史快照。


面向校园电竞赛事组织者的赛事运营工作区。当前项目以华东理工大学《无畏契约》校内赛为真实验证场景。

## 当前建设策略

工作台当前按 3 个负责人模块组织：

1. 报名与队伍
2. 赛程（抽签、排期、改期、BP、报分与晋级）
3. 赛事设置

不设置独立总览页；点击赛事直接进入赛程，生命周期和模块状态显示在侧栏。问卷星、腾讯文档、QQ群和微信群继续作为现有工具纳入产品流程，不预设必须全部替代。

## 运行项目

```bash
npm run dev
```

打开 `http://localhost:3000/admin` 查看赛事工作区。

## 当前实现与验收状态

- 网站定位为「华东理工大学电竞部」综合站，赛事是主要功能之一。
- 赛制配置已真正驱动抽签和对阵：除“4 队单败 BO1 → 3 场”和“16 队 GSL + 8 队双败 → 34 场”外，已支持本届目标赛制按真实赛果分三次完成“32 队入围赛 16 场 → 16 队 GSL 小组赛 20 场 → 8 队双败淘汰 14 场”，合计 50 场；未实现的拓扑会在创建时明确拦截。
- 规则引擎实现 HC-01~08 硬约束校验，20 个案例全部通过；改期闭环（申请→校验→批准→版本→通知）可用，批准强制重校验；另有完整闭环测试 100 例通过（`npm run test:loop`）与 BP 系统测试 44 例通过（`npm run test:bp`）。
- BP 工具完整可用：VCT 标准顺序（BO1/BO3/BO5）、两队队长自助（掷骰子比大小定先手/手动交换、逐步回退、3 秒同步）、裁判兜底代操作、结果写入选图并生成通知；地图池在赛事设置后台维护（13 张中文名地图目录 + 原画缩略图，默认启用排位图池 7 张，轮换替换人工完成），BP 房间卡片显示地图原画。
- 报名与队伍支持独立的「选手报名截止」和「队伍申报截止」：停止个人报名后仍可继续组队，停止队伍申报后才冻结名单调整。
- 负责人报名工作台支持选手审核、资料更正、代建与补人、正式名单确认、换人、个人/整队退赛和操作记录；修改使用赛事级原子写入，最新操作仅在未出现后续数据变化时允许撤销，避免覆盖玩家新报名。
- 报名工作台按状态汇总，支持搜索、审核筛选和每页 20 人，约 160 人规模下不依赖超宽表格；旧抽签读取逻辑不再自动回写整份报名数据。
- 赛事设置按赛事 ID 独立保存，负责人可在后台维护赛事信息、规则、地图池和玩家侧公开内容，无需修改代码。
- 赛事阶段与玩家侧可见性相互独立：负责人可先预览已保存的玩家页面，再显式发布或撤回；撤回不会把“报名中/比赛中”等运营阶段改回草稿。公开中的赛事保存仍需满足内容完整性，比赛中赛事还必须已有赛程。
- 负责人端与玩家端共用同一套语义化对阵画布：GSL 小组赛按“揭幕战→胜者/败者战→最终出线战”展示，双败淘汰按胜者组/败者组分轨，并在每场卡片标明胜负去向；窄屏使用画布内横向浏览，不造成整页溢出。
- 后台阶段驱动：模块状态和生命周期按赛事阶段动态计算；工作区一屏显示当前阶段目标、真实阻塞原因和唯一下一步入口，不允许点击未来阶段假装推进。玩家侧与后台共用同一阶段判定逻辑。
- 玩家赛事页按阶段只突出一个当前任务：筹备查看竞赛规程、报名提交参赛登记、分组查看首轮对阵、比赛查看有效赛程、赛后查看最终赛果；参赛选手、参赛队伍、赛事赛程和赛事对阵使用紧凑资料标签。竞赛规程采用暖色编辑排版，直接展示参赛程序、阶段晋级路径、赛事地图池、比赛程序、竞赛纪律、赛务异常、申诉裁决和奖金奖项；文案术语参考职业电竞赛事的信息层级并减少口语化，内容继续读取后台可编辑字段。
- 匿名测试赛已完成 50 场完整生命周期并产生冠军。赛后玩家页先展示冠军、总决赛比分与前三名，负责人赛程页转为只读；官网内容工作台会识别仍含赛前语言的赛事简介和页脚，提供基于最终赛果的建议并由负责人确认同步。

## 质量门禁

本地和 CI 跑同一条命令，避免出现「本地绿了、CI 红了」：

```bash
npm run gate
```

| 检查 | 命令 | 内容 |
| --- | --- | --- |
| 代码规范 | `npm run lint` | eslint |
| 类型检查 | `npm run typecheck` | tsc --noEmit |
| 测试 | `npm run test:all` | 15 个套件：规则引擎 20 例、闭环 100 例、BP 44 例、数据事务、报名、恢复、轮空、赛果、裁判、证据、报分、发布、运营 |
| 构建 | `npm run build` | Next.js 生产构建 |

CI 配置在 `.github/workflows/quality-gate.yml`，push 到 main 和提交 Pull Request 时自动运行。

只想跑单个套件时用 `npm run test:<名字>`，例如 `npm run test:referee`。

注意：本机构建需要先绕开环境的删除护栏，即 `CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run build`。
被拦的是 `.next` 构建缓存（已进 gitignore、可再生），不是代码问题；CI 不需要这个开关。
