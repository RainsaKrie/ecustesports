# Esports Operations Assistant

面向校园电竞赛事组织者的赛事运营工作区。当前项目以华东理工大学《无畏契约》校内赛为真实验证场景。

## 当前建设策略

工作台 v0.2 已收敛为 4 个负责人模块：

1. 策划案
2. 报名与队伍
3. 赛程（抽签、排期、改期、BP、报分与晋级）
4. 赛事设置

不设置独立总览页；点击赛事直接进入赛程，生命周期和模块状态显示在侧栏。问卷星、腾讯文档、QQ群和微信群继续作为现有工具纳入产品流程，不预设必须全部替代。

## 运行项目

```bash
npm run dev
```

打开 `http://localhost:3000/admin` 查看赛事工作区。

## 当前实现状态

- 网站定位为「华东理工大学电竞部」综合站，赛事是主要功能之一。
- 已跑通完整闭环：报名（扫码/时间窗口/人才市场组队，服务端落盘）→ 赛制抽签（种子分档/分组/对阵）→ 发布 26 场赛程（小组赛 12 + 8 队双败淘汰 14，胜败双路晋级）→ 排期/改期 → 比赛执行（逐局报分/晋级推进）→ 冠军产生 → 赛事回顾。
- 规则引擎实现 HC-01~08 硬约束校验，20 个案例全部通过；改期闭环（申请→校验→批准→版本→通知）可用，批准强制重校验；另有完整闭环测试 64 例通过（`npm run test:loop`）与 BP 系统测试 44 例通过（`npm run test:bp`）。
- BP 工具完整可用：VCT 标准顺序（BO1/BO3/BO5）、两队队长自助（先手掷硬币/交换、逐步回退、3 秒同步）、裁判兜底代操作、结果写入选图并生成通知；地图池在赛事设置后台维护（13 张中文名地图目录 + 原画缩略图，默认启用排位图池 7 张，轮换替换人工完成），BP 房间卡片显示地图原画。
- 报名与队伍支持独立的「选手报名截止」和「队伍申报截止」：停止个人报名后仍可继续组队，停止队伍申报后才冻结名单调整。
- 赛事设置按赛事 ID 独立保存，负责人可在后台维护赛事信息、规则、地图池和玩家侧公开内容，无需修改代码。
- 后台阶段驱动：模块状态和生命周期按赛事阶段动态计算，玩家侧与后台共用同一阶段判定逻辑。
- 数据落盘到本地 `data/site-config.json` 与 `data/events/{eventId}/`（公开报名/组队写接口 + 后台写接口，管理员鉴权保护）；尚未接入数据库和正式账号权限体系，上线前需通过环境变量配置管理员密码与签名密钥。
- **AI 能力尚未接入**：当前冲突解释和通知生成均为确定性代码实现，未接入任何 LLM。项目定位为「AI 赛事运营助手」，AI 接入是下一阶段核心工作。
