# Gate 6：部署方案决策稿

- 日期：2026-08-27
- 状态：付费服务器方案已停止；已确认 Vercel Hobby + Supabase Free + 自购域名
- 目标：在 500 元以内，为约 160 名选手、32 支队伍的校内赛事建立可公开访问、可备份恢复、风险可控的首轮部署
- 非目标：不为商业化流量设计多机集群，不在本阶段恢复 AI 接入，不先购买与方案无关的云产品

## 1. 必须先区分的两个目标

| 目标 | 要求 |
|---|---|
| 预发布验证 | 可通过公网域名访问，用于压测、安全检查、流程演练；可以接受临时域名或境外节点 |
| 真实校内赛事 | 校内玩家访问稳定，报名与赛果数据可恢复；若使用中国大陆服务器和正式域名，必须预留备案时间 |

同一个技术架构可以先部署到预发布环境，再切换到中国大陆正式环境。不能因为预发布页面能打开，就直接认定真实赛事部署通过。

## 2. 候选方案

### 方案 A：中国大陆单机生产架构

**组成**

- 腾讯云轻量应用服务器，中国大陆地域，建议 2 核 4 GB。
- Docker Compose 运行 Next.js、PostgreSQL 和 Nginx。
- 腾讯云 COS 保存上传图片与数据库备份。
- 正式域名、HTTPS、ICP 备案。

**预算基线**

| 项目 | 估算 |
|---|---:|
| 2 核 4 GB 轻量服务器 | 刊例价约 80 元/月 |
| 满足备案要求的 3 个月服务器 | 约 240 元 |
| 域名 | 以实际购买页为准 |
| COS | 当前新个人用户有 50 GB 标准存储 6 个月额度；请求和流量另计 |
| HTTPS | 可使用自动签发与续期的免费证书方案 |
| 预计总额 | 可控制在 500 元以内 |

**优点**

- 更符合校内玩家在中国大陆的真实访问环境。
- 单机架构足以承载本届规模，运维边界清晰。
- PostgreSQL 解决关键数据的原子更新和并发覆盖；COS 解决上传和异地备份。

**代价和风险**

- 中国大陆服务器绑定域名对外服务前需要 ICP 备案。
- 腾讯云当前要求备案用轻量服务器为中国大陆节点、包年包月且购买至少 3 个月。
- 首次备案包含平台初审和管局审核，必须提前开始，不能等比赛报名开放后再处理。
- 应用和数据库同机仍是单点；首轮依靠每日异地备份和恢复演练控制风险。

**结论**：推荐作为真实校内赛事方案。

### 方案 B：中国香港单机预发布架构

**组成**

- 腾讯云中国香港轻量服务器。
- 与方案 A 相同的 Docker Compose、PostgreSQL、Nginx 和 COS。
- 域名与 HTTPS，不办理中国大陆 ICP 备案。

**优点**

- 可以更快形成公网预发布环境，先做压测和安全验收。
- 与正式环境的应用架构一致，后续迁移成本较低。

**代价和风险**

- 中国大陆访问延迟和稳定性需要实际测试，不能仅凭本机或少量设备判断。
- 不建议未经真实网络验证就作为正式比赛唯一入口。
- 切换到中国大陆服务器时仍要完成备案。

**结论**：适合作为快速预发布方案，不直接替代正式方案。

### 方案 C：海外 Serverless + 托管数据库

**优点**：部署快捷，平台运维少。

**问题**：当前应用依赖 Node 运行时、本地文件写入和较多动态接口，需要先完成适配；中国大陆访问表现、跨境数据和多个服务账单会增加不确定性。

**原结论**：预算约束出现前不选。

**2026-08-28 更新**：负责人确认沿用趣灵的 Vercel 与自购域名发布方式，并接受 Supabase Free 承担数据库与图片。方案 C 现为当前执行方案，但必须在校内网络完成真实访问、承载、备份恢复与安全测试，不能因成功部署就直接通过 Gate 6。详细执行架构见 `Gate6-Vercel与Supabase部署架构.md`。

## 3. 原付费方案结论

预算内默认采用“大陆单机、先本地改造、备案后预发布”的路径：

1. 购买满足备案条件的中国大陆 2 核 4 GB 轻量服务器并开始备案。
2. 备案期间在本地完成容器化、数据库迁移、限流、安全和备份恢复开发。
3. 备案完成后先部署为预发布状态，不立即开放报名；在同一正式基础设施上完成公网压测和安全验收。
4. Gate 6 通过后才开放真实报名。

只有赛事时间明显早于备案进度时，才额外购买中国香港短期服务器。香港节点用于提前验证部署，不作为未经网络实测的正式赛事唯一入口。

负责人于 2026-08-27 补充“租用服务器超出预算”。因此本节不再作为当前默认执行方案，后续转入 `Gate6-零预算部署替代评估.md`。如未来获得学校资源、学生云额度或新增预算，再重新评估本方案。

## 4. 数据持久化设计

首轮不把现有全部 JSON 拆成复杂关系表。使用 PostgreSQL 的 JSONB 文档表承接现有数据模型，以最低改造成本获得事务、并发控制和备份能力。

建议表结构：

| 表 | 关键字段 | 用途 |
|---|---|---|
| `app_documents` | `scope`、`event_id`、`name`、`payload jsonb`、`version`、`updated_at` | 保存站点配置及赛事 registration/schedule/format/bp 数据 |
| `operation_audit` | `event_id`、`actor_type`、`action`、`target`、`metadata jsonb`、`created_at` | 保存关键负责人和玩家操作记录 |
| `rate_limit_events`（可选） | `key_hash`、`action`、`occurred_at` | 需要跨进程限流时使用；首轮也可由反向代理完成入口限流 |

更新规则：

- `readData/readEventData` 改为读取数据库文档。
- `updateData/updateEventData` 在数据库事务中锁定单行、读取、校验、更新并递增版本。
- BP、报名、约赛、报分和阶段推进禁止继续使用无版本校验的整文件覆盖。
- 原 JSON 文件只作为一次性导入源和可恢复备份，不再作为生产主数据。
- 导入程序必须可重复执行但不重复创建数据；迁移前后核对赛事数、选手数、队伍数、比赛数和冠军结果。

## 5. 生产安全基线

在部署预发布域名前必须完成：

1. 生产环境缺少 `AUTH_SECRET` 或 `ADMIN_PASSWORD` 时拒绝启动，删除生产默认值。
2. 管理员登录、报名、组队、约赛和 BP 写接口设置独立限流规则。
3. 管理员写接口校验同源请求，保留 HttpOnly、Secure、SameSite Cookie。
4. 配置 CSP、HSTS、防嵌入、防 MIME 嗅探、Referrer Policy 和 Permissions Policy。
5. 上传文件校验真实图片签名，使用随机对象名并存入 COS。
6. 记录登录失败、赛事发布、名单修改、排程审批、报分、结束赛事和删除赛事等关键操作。
7. 每日数据库备份到 COS，至少保留 7 个日备份；正式比赛日增加开赛前快照。
8. 建立 `/api/health`，同时检查应用存活和数据库可连接性。
9. 处理依赖审计中的高等级间接依赖告警并重新审计。

## 6. 负责人需要确认的决定

### D6-A：正式环境地域

- 推荐：中国大陆腾讯云，接受备案流程。
- 备选：中国香港仅作为预发布；是否能用于正式赛事必须通过校内网络实测。

### D6-B：预发布节奏

- 推荐：只购买大陆服务器；备案期间完成本地改造，备案后在同一服务器先做预发布验证。
- 加速备选：赛事时间紧张时，再购买香港短期预发布服务器并同步推进大陆备案。

### D6-C：首轮数据库成本

- 推荐：PostgreSQL 与应用同机，每日备份到 COS，控制在 500 元预算内。
- 更高可靠性：购买独立托管数据库；按当前刊例价可能突破总预算。

## 7. 依据

- Next.js 16.3 本地官方文档确认 Node.js Server 与 Docker 支持完整功能，自托管时建议在 Next.js 前使用反向代理处理异常请求、慢连接、请求体限制和限流。
- 腾讯云轻量应用服务器中国大陆通用型 2 核 4 GB 当前刊例价约 80 元/月。
- 腾讯云备案文档要求中国大陆轻量应用服务器采用包年包月并购买至少 3 个月；首次备案需经过平台与管局审核。
- 腾讯云说明中国香港及境外实例无需 ICP 备案，但地域一旦购买不能直接变更。
- 腾讯云 COS 新个人用户当前可获得 50 GB 标准存储 6 个月额度；请求次数和流量不在该免费存储额度内。
