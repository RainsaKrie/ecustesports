# Gate 6：零预算部署替代评估

- 日期：2026-08-27
- 状态：已确认采用 Vercel Hobby + Supabase Free + 自购域名
- 新约束：不租用付费服务器；优先使用本地资源、学校资源、学生额度或免费层
- 目标：在不产生固定服务器费用的情况下，完成公网预发布与受控真实测试

## 1. 本地保存是否可行

可以，但存在三种不同使用边界：

| 方式 | 可做什么 | 不能证明什么 |
|---|---|---|
| 只在本机运行 | 开发、功能回归、负责人操作、保留完整数据 | 玩家公网访问、真实网络承载、持续在线 |
| 校园局域网访问 | 同一网络内的现场测试 | 校外玩家访问、跨网络稳定性 |
| 本机 + 公网隧道 | 短时间向外部测试者开放 | 长期可用性、断电恢复、家庭/宿舍网络稳定性 |

因此，本地数据可以继续作为开发主数据和备份，但“本机可以打开”不能让 Gate 6 通过。

## 2. 零预算候选方案

### 方案 Z1：学校服务器或学校域名

**适用**：学校、学院、电竞社或指导老师能提供服务器、容器、数据库或可部署 Node.js 的空间。

**优点**：对校内网络通常更稳定；个人无需承担服务器费用；赛事主体与基础设施关系清晰。

**限制**：需要学校授权；可能限制后台服务、数据库、端口和自定义域名。

**定位**：真实赛事首选，但必须先确认资源能力与责任人。

### 方案 Z2：Azure for Students 学生额度

**适用**：拥有可验证的高校学生身份和学校邮箱。

**当前官方条件**：符合条件的高校学生可获得 100 美元、12 个月有效的 Azure 额度，无需信用卡；仍需控制资源类型和到期时间。

**优点**：不需要现金购买服务器；可以获得真实云环境、日志和数据库能力。

**限制**：中国大陆访问质量仍需实测；额度耗尽后资源会被停用；部署与成本监控比 Vercel 更复杂。

**定位**：零现金真实云环境的优先候选。

### 方案 Z3：Vercel Hobby + Supabase Free

**组成**：Vercel 部署 Next.js；Supabase 提供 PostgreSQL、对象存储和基础服务；预发布先使用平台子域名，通过后绑定负责人自购域名。

**当前免费边界**：

- Vercel Hobby 面向个人、非商业项目，包含免费函数、流量和自动 HTTPS；超出免费额度时项目可能暂停。
- Supabase Free 当前提供 2 个免费项目、每项目 500 MB 数据库和 1 GB 对象存储；不提供自动备份，长期不活跃项目可能暂停。

**优点**：部署最简单；不需要电脑持续在线；足以承载当前 160 人规模的功能与容量验证。

**限制**：

- 中国大陆校园网络访问必须实测，不能提前保证。
- Vercel Hobby 限于个人非商业用途；可用于本项目预发布和非商业验证，但若转为学校正式长期服务应重新检查使用条款。
- 免费数据库没有自动备份，必须由项目自行定时导出或在关键节点手动备份。
- 应用文件系统不能继续保存业务 JSON 或上传文件，仍需完成数据库与对象存储迁移。

**定位**：最省操作的零预算预发布方案；通过校内网络实测后，可考虑用于首轮受控非商业赛事，但必须保留人工兜底。

### 方案 Z4：本机 + Cloudflare Tunnel

**方式**：电脑运行 Next.js 和本地数据，`cloudflared` 通过出站连接生成公网入口；无需公网 IP。

**优点**：数据留在本机，不需要服务器费用；适合邀请少量玩家完成 1—2 小时的真实任务测试。

**限制**：

- Cloudflare 官方明确 Quick Tunnel 仅用于测试和开发，不承诺 SLA 或可用性。
- 电脑关机、休眠、断网或重启都会中断服务。
- 公开入口把本机应用暴露到互联网，仍需要生产密码、限流、安全头和备份。
- 不适合作为持续一个月赛事的唯一入口。

**定位**：短时测试工具，不是 Gate 6 正式部署方案。

## 3. 原候选顺序

按“可靠性优先、现金成本为零”排序：

1. 先询问学校、学院或电竞社是否能提供 Node.js/容器、PostgreSQL 和域名资源。
2. 同时申请 GitHub Student Developer Pack 或 Azure for Students 的 100 美元学生额度。
3. 若学校与 Azure 均不可用，采用 Vercel Hobby + Supabase Free 完成预发布，并在华理校园网和常用移动网络实测。
4. Cloudflare Tunnel 只用来提前做短时外部测试，不承担正式赛事。
5. 本地始终保留匿名测试赛和导出备份，但不作为唯一生产数据源。

## 4. 对当前技术方案的影响

无论选择 Azure 还是 Vercel + Supabase，都继续采用 PostgreSQL；不再为生产环境保留本地 JSON 写入。

- 本地开发：可运行本地 PostgreSQL，或连接单独的 Supabase 测试项目。
- 预发布：使用云端 PostgreSQL 和对象存储。
- 数据迁移：现有 JSON 一次性导入，迁移后核对 160 名选手、32 支队伍、50 场比赛和最终冠军。
- 备份：免费层没有足够恢复承诺时，由项目自行导出数据库与对象文件；关键阶段前额外生成快照。
- 降级：云服务不可用时，赛事负责人保留只读赛程导出和人工群通知，不允许在两个数据源同时写入。

## 5. Gate 6 仍然不变的标准

零预算不降低以下标准：

- 生产环境不允许默认管理员密码和默认签名密钥。
- 登录、报名、约赛和 BP 必须限流。
- 公开接口不泄露姓名、学号、联系方式和管理凭证。
- 并发报名和赛程写入不得覆盖数据。
- 必须完成一次备份恢复演练。
- 必须使用华理校园网、宿舍网和至少一种移动网络进行访问测试。
- 免费服务被暂停或不可用时，必须有人工兜底和可读取的最新导出。

## 6. 已确认组合

如果学校暂时不能提供资源，默认推荐：

> GitHub ＋ Vercel Hobby（Next.js）＋ Supabase Free（PostgreSQL、图片）＋自购域名＋本地定期备份。

负责人于 2026-08-28 确认沿用趣灵的 Vercel 与自购域名发布方式。赛事助手不复用趣灵的本地存储或 Upstash 主数据方案；具体架构、迁移边界与放行顺序见 `Gate6-Vercel与Supabase部署架构.md`。这套组合适合当前个人、非商业、160 人规模的预发布验证。只有完成真实网络测试、免费额度监控和恢复演练后，才能决定是否直接用于本届赛事。
