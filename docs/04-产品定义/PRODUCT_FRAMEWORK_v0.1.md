# AI 赛事运营助手：产品框架 v0.1

## 1. 产品定位

为校园电竞赛事组织者提供贯穿策划、报名、赛制、排程、比赛执行、通知和复盘的赛事工作区。产品不以替代所有既有工具为前提，而是统一关键业务状态、规则版本、审批责任和跨模块数据。

## 2. 当前建设原则

- 先搭完整信息架构，保证模块之间能够形成业务链路。
- 再根据真实办赛证据选择模块做深，不要求所有模块同时达到可用状态。
- 确定性规则不交给大模型判断；AI 主要处理自然语言、缺失信息、解释和生成。
- 赛制、赛程、发布和临时调整必须由负责人确认。
- 页面必须标明真实能力、Mock 数据和待接入能力，不能把界面完成当作产品验证。

## 3. 赛事生命周期

`策划 → 报名 → 抽签 → 排程 → 比赛执行 → 赛后复盘`

| 模块 | 上游输入 | 核心职责 | 下游输出 |
|---|---|---|---|
| 赛事策划 | 办赛目标、规模、资源 | 规则与里程碑初稿、赛事手册 | 报名规则、赛制候选 |
| 报名与队伍 | 问卷星提交、修改申请 | 清洗、异常识别、审核、名单冻结 | 最终队伍与选手名单 |
| 赛制与抽签 | 冻结名单、段位信息 | 阶段结构、种子池、抽签与晋级关系 | 对阵与依赖图 |
| 赛程中心 | 对阵、时长、阶段、资源容量 | 初始排程、冲突检查、版本发布、临时调整 | 当前唯一有效赛程 |
| 比赛执行 | 有效赛程、裁判资源 | 签到、BP、比分、异常、推进 | 比赛结果与后续对阵 |
| 通知中心 | 已批准的规则、赛程和比赛状态 | 分角色通知草稿、审核和发送记录 | 对外一致信息 |
| 赛事报告 | 全流程日志与赛果 | 运营指标、异常分析、对外战报和下届改进 | 复盘与可复用证据 |
| 赛事设置 | 负责人决策 | 基础信息、权限、工具连接和规则版本 | 所有模块的公共配置 |

## 4. 外部工具边界

- 问卷星：报名已内置，问卷星退场（或仅作宣传入口）。
- 腾讯文档：暂不考虑直连。
- QQ群与微信群：继续承担玩家触达；通知以复制/导出方式人工触达，暂不直连。
- AI 模型：尚未接入；AI 价值在冲突解释与通知生成，接入前先建测试集。

## 5. 当前与后续

当前已通过 Gate 2，完成跨模块数据模型（10 个对象）与报名内置方案，PRD v0.1 起草中。下一步深化赛程中心的临时改期闭环（P0）。
