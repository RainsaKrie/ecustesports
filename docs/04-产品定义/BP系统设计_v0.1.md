# BP 系统设计 v0.1（地图 Ban/Pick）

- 项目：《无畏契约》校园赛事 AI 排程协同助手
- 文档状态：草案，待负责人确认
- 日期：2026-08-17
- 承接：PRD_v1.2 F6「在线 BP 工具」；赛事当前流程「排期 → 报分」中的赛前环节

## 1. 背景与现状问题

现有 BP 工具（`/bp`、`/bp/[id]`）存在以下问题，需要先完成系统设计再改页面：

1. **BP 顺序错误**：当前固定「4 禁 4 选 + 决胜图」，7 张地图 4 禁后只剩 3 张，无法再 4 选，流程在 BO5 下必然卡死。
2. **无 BO 类型区分**：BO1/BO3/BO5 使用同一顺序，不符合真实赛制。
3. **状态不落盘**：BP 过程只存浏览器内存，刷新即丢；仅完成后把选图写入比赛记录。
4. **无回退**：选错地图只能整体重置。
5. **无完成通知**：PRD F6 要求 BP 完成后通知裁判。
6. **无先手权规则**：谁先 Ban/Pick 未定义。
7. **公开页无身份保护**：匿名可点但操作不生效，页面语义混乱。

## 2. 角色与场景

| 角色 | 职责 |
|---|---|
| 两队队长（操作人） | 赛前进入 BP 房间，轮流操作本方步骤；选错可联系裁判回退 |
| 裁判 | 兜底：可代任意一方操作、回退、整体重置、掷骰子 |
| 赛事负责人 | 复核 BP 结果、查看历史记录 |

核心场景：比赛排期后，两队队长各自打开该场比赛的 BP 房间，系统按赛制与先手权提示当前操作方；轮到本方时队长点击地图完成 Ban/Pick，对方实时看到；完成后系统把选图写入比赛记录并生成通知草稿；报分时逐局直接选择已确定的比赛地图。

### 2.1 队长身份（弱身份方案）

当前系统没有账号体系，采用「报名绑定身份」作为演示级弱身份：

- 选手报名后浏览器 localStorage 保存 `current-player-id`，系统据此识别其所属队伍与是否队长。
- 队长可操作本方步骤；成员只读；游客只读。
- 裁判/负责人（后台登录）始终可代任意一方操作、回退与重置。
- 弱身份可被伪造，仅适用于内部演示与单机测试；正式使用前必须接入账号体系（写入验收限制）。

### 2.2 跨设备同步

双方队长通常在不同设备操作，BP 会话落盘到服务器（`data/bp.json`）。房间页每 3 秒轮询一次最新状态，操作后立即刷新；不做 websocket。

## 3. BP 规则（核心）

### 3.1 地图池（后台可配置）

- 全量候选：13 张竞技地图目录（亚海悬城、源工重镇、隐士修所、霓虹町、森寒冬港、微风岛屿、莲华古城、裂变峡谷、深海明珠、日落之城、幽邃地窟、天枢云阙、盐海矿镇），每张带原画图片（public/maps）。
- 默认启用排位图池 7 张（前 7 张）；随排位轮换的替换由人工在「赛事设置 → 地图池」完成（缩略图卡片点选启用/停用），保存后 BP 房间与顺序计算即时生效。
- 最小约束：启用数不少于 5 张（BO5 需要 5 张）；不足时设置页给出提示，BP 房间拒绝启动对应 BO 场次。

### 3.2 各 BO 类型 BP 顺序（VCT 标准，已确认；顺序按池大小通用生成）

设地图池大小为 N，流程为：

| 赛制 | 通用规则 | 7 张池下的结果 |
|---|---|---|
| BO1 | 双方交替 Ban，直到剩 1 张 | 各 Ban 3 次，剩 1 张即比赛图 |
| BO3 | 双方交替 Ban 直到剩 3 张，再交替 Pick 2 张 | 各 Ban 2 次 → 各 Pick 1 次，剩 1 张为决胜图（图 3） |
| BO5 | 双方交替 Ban 直到剩 5 张，再 Pick 5 张 | 各 Ban 1 次 → 选满 5 张，无决胜图 |

- 每张地图只能被 Ban 或 Pick 一次，不可重复。
- Ban 从先手方开始交替；Pick 从先手方开始交替。
- BO3 决胜图、BO1 唯一图不用点选，系统自动判定剩余地图。
- 顺序由 BO 类型 + 地图池大小自动生成（纯函数），本轮不做手工自定义顺序。

### 3.3 先手权（A 侧默认，可掷骰子比大小，已确认）

- 比赛对阵中的 A 侧队伍默认为先手方。
- 赛前由裁判/任一方在房间内决定是否更换：提供「掷骰子比大小」按钮（双方各掷一颗 1–6，点数大者先手，平局重掷整轮）与「手动交换」按钮（仅裁判）。
- **为什么不是掷硬币**：硬币在页面上只有「交换 / 不变」一种表述，输的一方无法验证；骰子把两个点数都亮出来，谁先手当场可验算。见 D-BP-08。
- 骰子结果（双方点数）随会话持久化，刷新后仍在；「重置 BP」会连点数一起清除。
- 决赛等特殊场次可用种子高低约定，不做系统规则。

## 4. 数据模型

### 4.1 BP 会话（独立持久化，`data/bp.json`）

```ts
interface BPSession {
  id: string;            // BP-<matchId>
  matchId: string;
  boType: "BO1" | "BO3" | "BO5";
  firstTeamId: string;   // 先手方队伍 ID
  firstTeamSide: "A" | "B"; // 先手方在对阵中的原始侧
  actions: BPActionRecord[];  // 按序操作记录（ban/pick + 操作侧 + 地图 + 时间 + 操作人角色）
  currentStep: number;   // 下一步序号（0 起）
  status: "进行中" | "已完成";
  startedAt: string;
  completedAt?: string;
}
```

- 比赛与 BP 会话一一对应（按 matchId 唯一）。
- 操作记录额外记 `operatorRole: "team" | "referee"`，用于回溯责任。
- BP 完成后把选图列表写入比赛记录 `match.bpMaps`（现有字段），并生成通知草稿：
  `【BP 完成】Mxx 队伍甲 vs 队伍乙 地图：Bind、Haven（、决胜图 Split）。请裁判与双方确认后开赛。`

### 4.2 状态机

```
待开始（房间未创建）→ 进行中 → 已完成（选图写入比赛 + 通知草稿）
                   ↘ 已重置（回退到待开始，清空操作）
```

- 已完成、已报分或已冻结的比赛不能重新 BP。
- 进行中可逐步回退（撤销上一步，仅裁判或操作本方上一步的队长），也可整体重置（仅裁判）。

## 5. 系统交互与接口

### 5.1 接口

| 接口 | 方法 | 鉴权 | 说明 |
|---|---|---|---|
| `/api/data/bp?matchId=` | GET | 公开 | 读取会话（无则返回空 + 可启动信息） |
| `/api/data/bp` | POST | 弱身份 + 服务端校验 | 创建/推进/回退/交换先手/掷骰子/重置/完成 |

- BP 写接口为公开接口，但服务端按操作校验身份：操作本方步骤时请求携带 `playerId`，服务端校验该选手属于当前操作方队伍且为队长；`referee` 操作需管理员会话。
- 游客/非双方队伍成员的写请求一律 403。

### 5.2 顺序生成（纯函数）

`buildBPOrder(boType, poolSize)` 生成步骤数组，每步 = { side: "A" | "B"（先手方视角）, action: "ban" | "pick" }；BO3 末位、BO1 全程由「剩余地图自动判定」补位。`buildBPMaps(order, actions)` 由操作记录推导最终比赛地图列表。

### 5.3 页面职责

- 公开 `/bp` 列表：显示已排期比赛与其 BP 状态（未开始/进行中/已完成）与结果。
- BP 房间 `/bp/[id]`：队长/裁判操作界面（见《BP 页面设计》）。
- 比赛执行页：BP 入口显示会话状态；报分弹窗逐局选图来源 = 会话结果。

## 6. 异常流程

| 异常 | 处理 |
|---|---|
| 选错地图 | 回退上一步（本方队长或裁判可回退本方刚完成的一步；裁判可回退任意一步） |
| BP 中途弃权 | 整体重置，重新开始（仅裁判） |
| 重复进入 BP 房间 | 读取同一会话，不新建 |
| 已完成的比赛再次 BP | 拒绝，提示查看历史 |
| 游客/非双方队长操作 | 前端隐藏操作入口，接口 403 |
| 双方使用不同设备 | 3 秒轮询同步会话状态 |

## 7. 验收标准

| 编号 | 验收标准 |
|---|---|
| BP-AC-01 | BO1/BO3/BO5 三种顺序按 3.2 执行，任何步骤不出现可选图不足或剩余图冲突 |
| BP-AC-02 | 刷新页面后 BP 进度不丢失；重开房间读同一会话 |
| BP-AC-03 | 完成后比赛记录写入选图（含决胜图），通知草稿生成于通知中心 |
| BP-AC-04 | 逐局报分的地图选项 = BP 结果，且顺序一致 |
| BP-AC-05 | 回退上一步后状态与展示一致；已完成比赛不可回退 |
| BP-AC-06 | 先手权可通过掷骰子/手动交换，并体现在操作提示中；点数随会话持久化 |
| BP-AC-07 | 仅双方队长可推进本方步骤，裁判可代操作；游客与成员只读 |
| BP-AC-08 | BP 系统纯函数逻辑测试全通过（含三种 BO 全流程与边界） |
| BP-AC-09 | 地图池在后台停用某张图后，BP 房间不再出现该图；启用数 < 5 时设置页提示 |
