# 工作台系统设计 v0.2

- 项目：《无畏契约》校园赛事 AI 排程协同助手
- 文档状态：已确认（2026-08-18，2026-08-25 按 D-055 删除策划案模块）
- 适用范围：后台工作台（/admin）的全部界面与交互
- 关联：`docs/06-原型设计/UI设计规格_v0.2.md`（视觉规范）

---

## 一、设计目标与原则

工作台是**真实可用的办赛系统**，不是作品集演示。据此确立四条原则：

1. **删解释性文案**：不出现「赛事提示」「数据保存在本地」这类向用户解释系统的灰色文字和蓝色提示卡；界面只说该做什么、该填什么。
2. **删重复**：信息只出现一处（如「全部功能」与侧边栏重复即删）；数据只填一次（赛制在新建比赛时填，策划案不再填）。
3. **保持边界**：赛制抽签与赛程执行合为赛程模块；策划案属于独立文档，不在办赛系统内重做文档编辑器。
4. **操作直觉化**：负责人面对一个核心视图（对阵图）完成主要动作，而不是在列表里翻找。

视觉上遵守 UI 规格 v0.2：无圆角、无黑卡片、品牌红强调、ink 结构线、白卡片。

## 二、信息架构

```
L0  工作台入口（导航栏「工作台」）
L1  赛事列表 /admin
    ├── 赛事列表（每届并列同层次，当前赛事只加「当前」标记，不放大）
    └── ＋ 新建赛事（两步创建，见「四」）
L2  赛事工作区 /admin/events/[id]（3 个模块，编号 01 起）
    ├── 01 报名与队伍
    ├── 02 赛程（核心）
    └── 03 赛事设置
```

- 点击「工作台」进入 `/admin` 赛事列表，**不**直接跳进某届赛事。
- 点击列表中的某届赛事 → 直接进入它的「02 赛程」（对阵图是办赛主场）。
- **无独立总览页**。阶段运营状态与模块状态徽标溶解到侧边栏：
  - 侧边栏显示「筹备 → 报名 → 分组 → 比赛 → 赛后」作为只读状态，不允许点击未来阶段假装推进；
  - 状态区同时展示当前目标、由真实赛事数据计算的阻塞原因和一个优先下一步入口，阶段切换与发布仍由负责人确认；
  - 每个模块名后挂状态徽标（如报名期「报名与队伍」标红「报名中」、赛程标「待抽签」），用于补充模块状态，不重复承担主任务提示。

## 三、三个模块

### 01 报名与队伍

- 保留**报名入口**（每届赛事独立二维码 + 链接，队长扫码进入玩家侧报名/建队）。
- **单列 + 切换**：选手列表和队伍列表不同时并排，做成一个列表，顶部 tab「选手 / 队伍」切换。
- 术语用真实办赛语境：**「选手报名截止」「队伍申报截止」**（不用「冻结名单」）。
- 后台保留「代建队伍」弱化入口，主职是审核、截止。
- **删除**：顶部提示卡、4 张统计卡。

### 02 赛程（核心，★）

**合并**「赛制与抽签」+「赛程与执行」，核心是一张**对阵图**，全程在这张图上完成。

**对阵图是骨架，抽签是填位**：

1. **骨架（抽签前）**：赛制配置生成完整对阵图结构——所有空位卡片都在，显示「待抽签」占位。
2. **抽签（裁判直播操作）**：见「五、抽签面板」。抽签把已报名队伍逐队填入空位。
3. **排期**：对阵图上的比赛未排期时显示「排期」，点击设置时间（校验硬约束）。
4. **BP**：已排期的比赛，点对阵图上的比赛 → 进入/查看地图 BP。
5. **报分**：在对阵图上点比赛 → 弹出报分框录入比分。
6. **晋级**：报分后胜者自动推进到下一轮，对阵图实时更新。

**删除**：提示卡、统计卡、改期申请队列/版本历史/通知草稿附属区块（改期操作仍在对阵图上）。

#### 对阵关系画布

- 负责人端与玩家端共用同一套关系结构和同一份赛程数据，负责人端仅在比赛卡片上增加操作入口。
- GSL 小组赛按组展示“揭幕战 → 胜者/败者战 → 最终出线战”，避免把四组比赛混成按时间排序的列表。
- 双败淘汰分为胜者组、败者组两条轨道，每条轨道按轮次横向展开；总决赛归入胜者组主线末端。
- 每场比赛卡片明确显示“胜 → 下一场”和“败 → 下一场/淘汰”，关系以实际 `nextWinnerMatchId`、`nextLoserMatchId` 为准，不在界面写死。
- 桌面端优先完整利用工作区宽度；窄屏只允许对阵画布内部横向浏览，并给出“左右滑动查看完整晋级路径”提示，页面本身不得横向溢出。

### 03 赛事设置

可编辑项**大幅精简、清晰分组**，只留办赛真正需要改的：

| 分组 | 可编辑项 |
|---|---|
| 赛事信息 | 名称、主办方、状态、报名起止、比赛日期 |
| 参赛规则 | 规则列表（增删改） |
| 地图池 | 启用/停用地图（缩略图卡片） |
| 公开内容 | 首页文案、主视觉（如需） |

删除与赛事运行无关的琐碎字段（站点品牌、SEO、导航文字等全站级配置下放或隐藏）。

#### 发布与玩家侧预览

- 赛事运营阶段与玩家侧公开状态独立维护；筹备中可以提前公开，撤回也不改变报名中、比赛中等真实阶段。
- 负责人只能发布已经保存且通过身份、简介、赛制、规则、地图池等检查的版本；报名中需额外满足报名日期顺序，比赛中还必须已有赛程。
- “预览玩家页面”读取最近一次保存的赛事、报名和赛程数据，并以明显横幅提示负责人当前是否尚未公开。
- 修改尚未保存时，发布与撤回不可操作，避免负责人预览或发布到旧版本。
- 公开与撤回由负责人显式确认，不由普通设置保存、赛事阶段变化或切换当前赛事自动触发。

#### 赛事归档与删除

- 真实往届赛事使用归档，保留报名、赛程、赛果和 BP 数据。
- 测试或误建赛事只有在未公开且处于筹备中或已归档状态时才能永久删除。
- 永久删除必须输入完整赛事名称确认，并同步清理赛事独立数据；系统至少保留一场赛事。

## 四、新建赛事（两步流程）

新建赛事只负责建立系统运行所需的赛事对象，不承担独立策划案写作。

```
新建赛事
├── ① 基础信息：名称、主办方、游戏、报名/比赛时间
└── ② 赛制配置：几个阶段、每阶段赛制类型、队伍数、BO 几

完成 → 赛事建好并进入赛事设置，审核规程与玩家页面后再发布
```

**赛制配置（核心）**：
- 阶段列表，可**增删阶段**（如入围赛、小组赛、淘汰赛、半决赛…）。
- 每个阶段配置：**赛制类型**（单败淘汰 / 双败淘汰 / GSL 小组 / 单循环）、**队伍数**、**BO 几**。
- 系统**实时计算**并展示：总场次、总比赛时长。

**数据复用**：赛制配置同时——
- 驱动「02 赛程」生成对阵图骨架；
- 自动生成玩家赛事手册中的竞赛赛制条款。

赛制只填一次，两处使用。

## 五、抽签面板（裁判直播操作）

抽签是**裁判在直播时屏幕共享、现场操作**的面板，做成全屏、大、清晰、有仪式感。

```
┌──────────────────────────────────────────────┐
│  小组赛抽签 · 直播投屏模式              [退出]  │
├───────────────┬──────────────────────────────┤
│ 种子池         │  对阵图（A/B/C/D 组）           │
│ 1号池 4 队     │  A组 ▢▢▢▢   B组 ▢▢▢▢          │
│ 2号池 4 队     │  C组 ▢▢▢▢   D组 ▢▢▢▢          │
│ 3号池 4 队     │  （空卡片等待填入）              │
│ 4号池 4 队     │                              │
├───────────────┴──────────────────────────────┤
│           [ 抽下一队 ]   [ 一键抽完 ]           │
└──────────────────────────────────────────────┘
```

- **逐队抽签**（直播用）：点「抽下一队」，系统从当前池随机抽一队，卡片翻转揭示、填入对阵图空位——一次一队，直播有节奏、有悬念。
- **一键抽完**（非直播快速模式）：直接填完全部空位。
- 抽签规则（种子分档、首轮 1 号池对 4 号池等）在面板上以种子池形式呈现。
- 抽签完成后，初始第一轮对阵确定，回到对阵图查看真实对阵。

抽签面板与赛程执行共用同一张对阵图，不割裂。

## 六、数据模型

| 层 | 位置 | 内容 |
|---|---|---|
| 站点级 | `data/site-config.json` | 站点品牌/导航/首页文案 + `events[]`（每届赛事元信息）+ `currentEventId` |
| 赛事级 | `data/events/{eventId}/` | `registration.json`（选手+队伍）、`format.json`（赛制定义+对阵）、`schedule.json`（赛程）、`bp.json`（BP 会话） |
| 模板库 | `src/lib/scheduling/format-templates.ts` | 赛制类型定义（单败/双败/GSL/循环），供配置器选择，非整套预设 |

---

## 七、阶段驱动

赛事阶段「筹备 → 报名 → 分组 → 比赛 → 赛后」由 `status` + 报名时间窗口 + 是否有赛程自动判定，后台可手动覆盖。

- 阶段决定侧边栏生命周期高亮、各模块状态徽标；
- 玩家侧主 CTA 与默认 tab 同步跟随。

---

## 八、已删除 / 暂缓

- **通知中心**：删除（当前无需要通知的内容；后续如需，通知草稿回到对应操作处生成）。
- **赛事报告**：暂缓（从导航移除，数据逻辑保留，赛后需要时再设计）。
- **策划案**：从系统移除，继续作为独立文档完成；不在工作台内重建 Word 式写作能力。
- **任务中心（独立总览页）**：删除（信息溶解到侧边栏生命周期条 + 模块状态徽标）。
- **全站级配置**（站点品牌/SEO/导航文字等）：从赛事设置下放/隐藏。

## 九、开发顺序建议

1. 导航重构（L1 并列列表 + 3 模块编号 + 生命周期条入侧栏 + 模块状态徽标）
2. 02 赛程对阵图（骨架 + 报分弹框，核心）
3. 抽签面板（裁判直播，逐队填位）
4. 新建赛事两步流程（基础信息 + 赛制配置）
5. 01 报名（单列切换 + 报名截止术语）+ 03 设置精简
6. 全站删提示卡/统计卡/灰字
