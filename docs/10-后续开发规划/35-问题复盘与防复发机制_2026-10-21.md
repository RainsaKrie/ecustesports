# 问题复盘与防复发机制（全站 UI 改造阶段）

> 触发：本阶段同一类问题反复出现（顶栏对齐改了三版、分组改了两版、
> 海报"重复"改了两版、CSS 规则被吞两天没人发现）。
> 本文回答三件事：**为什么反复、偏离了什么、怎么不复发**。

---

## 结论（先行）

**反复出现的不是"同一个 bug"，是同一个结构性缺口：** 这套工程**只能验证代码合法，不能验证界面正确**。

| 缺口 | 证据 |
|---|---|
| 基准只覆盖 1 页，其余 31 页靠各自发挥 | v8 样板只有赛程一页 |
| 门禁只查代码，不查渲染 | `gate = lint + typecheck + test:all + build`，**45 套测试里 CSS 语法 0 套、视觉 0 套** |
| 23 条硬约束写在文档里，没有任何一条被机制化 | 方案文档 32 号，约束靠人记 |
| 我判断"改没改好"的依据，长期是错的 | 用 SSR 空壳判断客户端渲染（3 次）、用 CSS 变量写在子元素上（1 次） |

---

## 一、根本原因（四条，按影响排序）

### 1.1 基准不完备，导致"每个页面都是即兴创作"

v8 样板是一页**赛程页**。而实际改造覆盖 31 页，包括管理端 13 页、裁判端、BP 房间、表单页 ——
这些在样板里**没有任何参照**。

→ 结果：每页都由我临时判断"应该长什么样"，于是：
管理端用了 `1500px` 而公开面 `1360px`；表单控件没有统一形态；地图名换行、卡片被拉长。

**这不是失误，是缺少规格。**

### 1.2 验证层错位：门禁验证的是"代码合法"，不是"界面正确"

`npm run gate` = lint + typecheck + 45 套测试 + build。它能保证：类型不炸、构建能过、逻辑断言成立。

它**保证不了**：布局对没对、颜色生效没生效、两条 CSS 规则是否互相抵消、媒体查询还有没有规则体。

**本阶段至少 6 个问题属于"门禁全绿但界面是错的"**：双 auto 抵消、128px 空档、
两张不同海报、分组被拆成 2 人组、媒体查询空规则体、`useState` 位置错误带来的静默失效。

### 1.3 CSS 集中在一个文件、靠层叠覆盖累积

`pub-theme.css` 里 `.site-nav` 相关规则一度有 **9 条**、`.ui-row` 13 条。
"最终生效值"要靠**读完全部规则**才能确定，于是出现：规则明明在线上、却因为另一条同选择器
规则在后面而失效；以及我用脚本压注释时**吞掉了两条规则体**，两天没人发现。

### 1.4 我判断"有没有改好"的依据，多次选错层

| 错误依据 | 后果 |
|---|---|
| 用 curl 抓页面 HTML 判断客户端渲染结果 | 看到的是空壳，据此误改两版分组 |
| 在子元素上改变量，期望影响祖先的伪元素 | 首页海报没变，正确结论被推迟一轮 |
| 凭"规则写对了"判断"会生效" | 双 auto 互相抵消，改了两版才核对线上 CSS |

## 二、偏离示范与约束的具体环节

| # | 约束出处 | 我做的 | 偏离 |
|---|---|---|---|
| 2.1 | v8 容器 1100 / 内边距 28 | 按你要求放宽到 1360 | **只改了主容器**，站头内层仍是 1100 → 窄 260px，按钮"看着没到边" |
| 2.2 | 方案 §P1 按钮 3 变体 | 加了 `danger`（第 4 个） | 合理，但**没回写文档**，文档至今写"3 变体" |
| 2.3 | v8 字号 11.5 / 13.5 / 14.5 / 22 | 收成 11 / 13 / 15 / 17 四档 | **与样板数值不一致**，且未记录"为什么改" |
| 2.4 | 方案「不能两份都留」 | 新增 `ui-chip` 后 0 处使用 | 新版约束（未使用的样式是负债）没被遵守，事后才删 |
| 2.5 | v8 分组积分按组切换 | 我做成 4 组竖排 | 页面被拉长，你提了两次才改 |
| 2.6 | 方案「构建不依赖数据库」 | 未在开工前核对 | 生产部署失败，事后才补 try/catch |

## 三、缺失的校验步骤

| 缺什么 | 应该在哪一步 | 现状 |
|---|---|---|
| CSS 语法校验 | 提交前 | **无**（`build` 用的解析器容忍错误） |
| 样式改动后的"生效值"核对 | 改完立刻 | **无**，靠肉眼 |
| 视觉回归（截图对比） | 合并前 | **无**（本机无无头浏览器） |
| 文档约束 → 代码的映射表 | 开工前 | **无** |
| 改完回写文档 | 提交时 | **偶尔**，多数不写 |

---

## 四、可落地的纠正措施

### 4.1 立刻可做（半小时内）

1. **`test:css` 接进门禁**：`postcss.parse` 解析三个 CSS 文件，语法不过直接红。
   —— 本阶段那个"两天没人发现"的规则体被吞，这条能拦住。
2. **`test:css-dupes` 接进门禁**：检测同一选择器出现超过 N 次（当前阈值 3），
   超了报警，把"层叠累积"挡住。
3. **文档与代码一致性检查**：按钮变体数、字号档位数这类数字，写在文档里就同时写在代码常量里，
   由测试比对。

### 4.2 需要环境支持（等你决定）

4. **视觉回归**：需要无头浏览器。本机 `playwright-cli` 插件缺依赖、装 `@playwright/cli` 超时。
   若能装通，每次提交对 6 个关键页面截图，与基线比对。
5. **样式生效值快照**：用浏览器 `getComputedStyle` 导出关键元素的最终值存成 JSON，
   下次改动 diff 这个文件 —— **这比截图更稳，不受字体渲染影响**。

### 4.3 流程层面

6. **一改一验**：每改一处视觉，**立刻**用可用手段验证（能查数据就查数据、能查 CSS 就查 CSS），
   验不到就**说验不到**，不往下改第二处。
7. **改前先读约束**：动手前把那 23 条过一遍，尤其是"不能两份都留""构建不依赖数据库"这类。

## 五、防复发检查清单

### 改样式前

- [ ] 这条规则**由谁消费**？（变量写在子元素、消费者在祖先上，等于没改）
- [ ] 同一个选择器**已经有几条规则**？（超 3 条先合并）
- [ ] 这个尺寸是**固定值**还是**相对比例**？（固定值用 px，相对比例可以用 rem）
- [ ] 样板里**有没有对应结构**？（没有就是即兴创作，要写进文档）

### 改完立刻

- [ ] `node -e "require('postcss').parse(...)"` 语法过没过？
- [ ] 这条规则**在最终 CSS 里还在吗**？（被后面的同选择器覆盖了吗）
- [ ] 相邻区块的**两端**分别对齐谁？（遮罩顶部对站头、底部对下一段）
- [ ] 独立设宽的容器（站头 / 页脚 / 弹窗）**同步了吗**？

### 验证时

- [ ] 我验的是**渲染结果**还是**空壳**？（客户端渲染的东西，curl 一定拿不到）
- [ ] 能查数据层吗？（调公开接口比重读代码可靠）
- [ ] 验不到时，**明确说了吗**？（不许把"提交了"当成"改好了"）

### 提交时

- [ ] 文档里的数字（变体数、档位数）**与代码一致吗**？
- [ ] 新增的东西**有人用吗**？（0 处使用 = 负债）
- [ ] 锁行文件**加了几行就还了几行**吗？
