# AI 数据与评测工作包 v1.0

- 轨道：C
- 目标：在不接入生产业务的前提下，判断赛果截图识别是否具有稳定、可量化的增量价值
- 当前许可：需求调查、授权样本、脱敏、标注、离线框架和模型对比
- 当前禁止：生产入口、生产数据写入、自动报分、自动晋级、自动审核

## 1. 基本原则

1. 先证明问题值得解决，再证明模型能识别。
2. 非 AI 裁判报分流程必须是对照基线。
3. 模型输出只是候选数据，不是正式赛果。
4. 评测必须同时覆盖准确、拒答、失败、延迟、成本和实际节省时间。
5. 真实图片必须获得授权并脱敏；原始含个人信息图片不得进入 Git。
6. 不因为求职展示而放宽生产安全门槛。

## 2. AIE-00：现状调查与人工基线

### 目标

确定真实报分问题的频率、成本和责任链，避免为低频动作建设复杂 AI。

### 调查对象

- 赛事负责人至少 1 名；
- 实际裁判至少 2 名；
- 如需要，询问负责汇总或发布赛果的工作人员。

### 需要记录

1. 比赛结束后由谁截取、发送、查找和录入赛果；
2. 一届比赛总场次和实际报分次数；
3. 单场从结束到官网更新的中位时间；
4. 裁判手工填写字段所需时间；
5. 管理员查图、确认和转录所需时间；
6. 漏报、错报、重复报分、找错比赛和修改赛果的次数；
7. 常见截图页面、数量、设备和画质；
8. 裁判是否愿意使用独立手机报分入口；
9. 哪些比赛需要负责人强制复核；
10. 目前群聊流程有哪些不可替代的便利。

### 建议记录表

| 字段 | 示例 |
|---|---|
| 比赛 ID | M01 |
| BO | BO3 |
| 截图数量 | 2 |
| 裁判操作秒数 | 45 |
| 管理员操作秒数 | 70 |
| 从结束到发布分钟数 | 12 |
| 是否发生修改 | 否 |
| 问题类型 | 找图/转录/错配/无 |
| 是否适合自动预填 | 待判断 |

### Gate AIE-00

出现以下任一情况，停止 AI 方向：

- 单场手工填写中位时间不超过 30 秒；
- 管理员无需二次转录；
- 一届比赛量不足以形成稳定成本；
- 裁判认为上传截图比直接填分更麻烦；
- 无法合法收集有代表性的样本。

### 交付物

- 访谈记录的脱敏摘要；
- 当前流程图；
- 人工耗时和错误基线；
- Go / No-Go 决策；
- 如继续，样本需求清单。

## 3. AIE-01：样本治理、标注规范与评测集

### 目标

形成可重复、不会泄露个人信息、能够覆盖失败情况的视觉评测集。

### 样本分层

| 类型 | 最低数量 | 目的 |
|---|---:|---|
| 标准清晰截图 | 15 | 验证理想输入上限 |
| 手机压缩/裁剪截图 | 10 | 验证真实传播损失 |
| 模糊、遮挡、缺字段 | 8 | 验证拒答能力 |
| 多局、多图、多张证据 | 8 | 验证系列赛组合 |
| 队伍顺序相反、名称干扰 | 5 | 验证比赛上下文约束 |
| 非赛果图片或错误游戏页面 | 4 | 验证无效输入识别 |

总数至少 50 个案例；同一张图的轻微裁剪不应被当作完全独立的多个案例。

### 标注字段

- case ID；
- 图片类型和来源类别；
- 游戏和页面类型；
- 已知比赛双方；
- BO 类型；
- 每局地图；
- 每局双方比分；
- 系列大比分；
- 胜方；
- 图中不可确定的字段；
- 应当拒答的原因；
- 是否包含个人信息及脱敏记录；
- 两名标注者及分歧处理结果。

### 数据拆分

- 开发集：用于调整提示词和解析；
- 验证集：用于阶段性比较；
- 冻结测试集：最终 Gate 使用，执行模型不得读取人工答案；
- 真实影子集：上线后产生，不能回写污染冻结测试集。

同一比赛、同一原图及其裁剪变体必须放入同一数据分组，防止数据泄漏。

### 隐私要求

1. 原始图片放在受控私有空间，不进入仓库。
2. 仓库只允许保存经确认脱敏的样本，且优先保存 manifest 而不是图片。
3. 玩家昵称、聊天、好友信息、手机号、学号和社交账号按必要性遮盖。
4. 保存授权来源、用途、访问人和删除时间。
5. 模型供应商的数据保留政策未确认前，不上传真实图片。

### 交付物

- 样本授权和脱敏规范；
- 标注指南；
- 数据 manifest schema；
- 标注一致性报告；
- 冻结集哈希和版本；
- 不含答案的模型输入集。

### 完成定义

- 两名标注者对关键字段达成一致；
- 分歧案例有负责人裁决；
- 测试集对模型执行者保持盲测；
- 仓库和日志中不存在未经批准的个人信息。

## 4. AIE-02：提供商无关离线评测框架

### 目标

建立可替换模型、可复现、与生产业务隔离的离线执行和评分框架。

### 框架分层

1. 数据读取：只读取授权的 manifest 和指定图片；
2. 输入构建：比赛上下文 + 图片；
3. 模型适配器：不同供应商使用统一接口；
4. 输出解析：严格结构化 schema；
5. 确定性复核：复用 BO 和比分规则；
6. 评分：字段级准确率、案例级可用率和拒答表现；
7. 记录：模型、版本、提示词、参数、延迟、token/图片成本和错误；
8. 报告：不包含密钥和原始敏感图片。

### 输出协议

沿用专项计划中的结构化字段，并额外记录：

- `provider`
- `model`
- `promptVersion`
- `schemaVersion`
- `startedAt`
- `latencyMs`
- `usage`
- `parseError`
- `validatorErrors`

### 必须提供的对照

- 人工手工填写基线；
- 不使用视觉模型的固定表单；
- 至少一个多模态模型方案；
- 如有第二模型，只在同一冻结输入上比较。

不能只比较两个模型而不比较“根本不用 AI”。

### 建议修改范围

- `tools/ai-eval/` 下新增独立目录；
- `docs/05-规则与AI验证/评测数据/` 下只放 schema、manifest 或确认可入库的脱敏数据；
- `package.json` 增加离线命令时须在 SYS-01 合并后执行。

### 禁止

- 不导入生产应用运行时；
- 不增加网页按钮或 API；
- 不将供应商 SDK直接散落进业务组件；
- 不提交 `.env`、密钥、原始输出中的个人信息；
- 不在执行时读取参考答案；
- 不修改旧的文本冲突评测结果冒充视觉评测。

### 验收清单

- [ ] 无密钥时能使用 mock adapter 完成框架自测；
- [ ] schema 错误被明确记录而不是自动修补；
- [ ] 每次运行有唯一 run ID；
- [ ] 断点、超时和部分失败不会丢失已有结果；
- [ ] 同一输入和配置可以复现评分；
- [ ] 评分脚本不依赖模型自报置信度；
- [ ] 报告区分模型错误、解析错误、输入不足和规则冲突；
- [ ] 不访问生产 API 或数据库。

## 5. AIE-03：模型对比与 Gate AI-2 报告

### 目标

用冻结数据回答“AI 预填是否比纯手工流程更值得继续”。

### 核心指标

#### 字段正确性

- 胜方精确匹配率；
- 系列大比分精确匹配率；
- 单局比分精确匹配率；
- 地图精确匹配率；
- 整个案例全部关键字段正确的比例。

#### 安全与拒答

- 无效输入正确拒绝率；
- 关键信息不足时正确拒绝率；
- 有效输入误拒率；
- 严重虚构次数；
- 未被规则校验发现的事实错误次数。

#### 产品价值

- 理论减少的手工字段比例；
- 预计核对和修改时间；
- 与纯手工表单相比的总操作时间；
- P50/P95 响应时间；
- 单场成本和一届赛事总成本。

### Gate AI-2 硬门槛

- 胜方和系列大比分精确匹配率不低于 98%；
- 单局比分和地图字段精确匹配率不低于 95%；
- 无效或缺失关键信息时不得猜测；
- 严重虚构事实为 0；
- 至少 80% 有效样本生成可用预填；
- 非法 BO 结果 100% 被确定性规则拦截；
- 预计能够减少至少 50% 手工字段输入。

### 决策输出

- Go：进入影子运行设计；
- Retest：仅当失败来自可修正的输入规范或提示词问题；
- No-Go：准确率、拒答或实际操作收益不足；
- Stop：出现无法接受的隐私、成本或事实安全问题。

不允许使用“总体感觉不错”代替逐项结论。

## 6. AIE-04：影子运行

### 启动条件

- RPT-07 非 AI 裁判报分综合验收通过；
- AIE-03 得出 Go；
- 产品负责人批准真实赛事影子范围；
- 模型数据保留和隐私条件已确认；
- 服务端功能开关默认关闭并可随时停用。

### 运行方式

裁判仍按手工流程提交。模型在后台读取同一份受控证据并生成候选结果，但：

- 不展示给裁判；
- 不写入正式赛果；
- 不改变异常队列；
- 不触发通知、BP 或晋级；
- 只与裁判最终提交结果离线比较。

### 需要记录

- 原始提交 ID；
- 模型运行 ID；
- 输出 schema 版本；
- 与正式结果的字段差异；
- 失败分类；
- 延迟和成本；
- 如果启用预填需要人工修改的字段。

### Gate AI-3

- 真实数据准确率不低于离线门槛；
- 未发现新的严重失败类型；
- 能证明预填可以降低至少 50% 操作时间或字段输入；
- 单场成本和响应时间可接受；
- 删除、审计和停用机制经过验证。

## 7. AIE-05：生产预填立项评审

本工作包只做是否立项的评审，不默认开发。

评审必须回答：

1. 非 AI 裁判报分已经减少了多少管理员工作；
2. AI 在此基础上还增加多少价值；
3. 裁判是否会因核对 AI 而花费更多时间；
4. 哪些字段允许预填，哪些必须人工输入；
5. 模型失败时是否可以无感回到手工流程；
6. 是否需要单模型、双模型或根本不需要 AI；
7. 成本、隐私和维护责任由谁承担；
8. 是否有足够真实证据支撑求职材料中的结论。

只有产品负责人明确批准后，才另建生产预填开发计划。

## 8. 与原文本 AI 评测的关系

现有冲突解释 20 例评测可以保留用于验证结构化输出、提示词版本和盲测流程，但它与视觉赛果识别是不同任务：

- 旧任务输入是已经结构化的规则事实；
- 新任务输入包含图片和不完整视觉证据；
- 旧任务不能证明 OCR、图像理解、拒答或截图隐私能力；
- 两套数据、指标、报告和结论必须分开。

## 9. 给执行 AI 的最终限制

- 不修改生产页面；
- 不调用生产数据写接口；
- 不处理未经授权的真实图片；
- 不把模型输出称为“审核结果”；
- 不把截图识别称为“验真”或“反作弊”；
- 不读取冻结测试集答案后再生成模型结果；
- 不因单次演示成功宣称 Gate 通过；
- 不跳过非 AI 对照基线；
- 不在 AIE-03 Go 之前启动影子运行；
- 不在 AIE-04 Go 之前提出生产 AI 入口合并请求。
