# 首轮派工清单 v1.0

- 目的：让负责人可以直接按顺序向其他 AI 派发任务
- 当前原则：先冻结事实和领域合同，再允许并行开发
- 最大建议并行数：3 个开发任务；高冲突任务只允许 1 个

## 1. 现在立即派发

### 任务 1：SYS-00 基线冻结与问题台账

- 类型：只读审计与文档
- 执行者：项目基线 AI
- 是否改代码：否
- 前置依赖：无
- 结果：当前提交、测试、生产对应关系和唯一 P0/P1 问题清单
- 参考：`01-生产系统完善工作包_v1.0.md` 第 2 节

### 任务 2：RPT-00 裁判报分领域设计与 ADR

- 类型：产品与技术设计
- 执行者：领域架构 AI
- 是否改代码：否
- 前置依赖：可读取 SYS-00 初步结论，但不必等待全部结束
- 结果：对象、状态机、权限矩阵、恢复矩阵、API 合同和功能开关方案
- 必须由彭杰确认十项产品决策后才算通过
- 参考：`02-裁判报分基础设施工作包_v1.0.md` 第 2 节

### 任务 3：AIE-00 调查模板与人工基线设计

- 类型：研究准备
- 执行者：AI 产品评测 AI
- 是否改业务代码：否
- 前置依赖：无
- AI 可完成：访谈提纲、记录表、指标定义、样本登记模板
- 必须由人完成：真实裁判访谈、实际耗时记录、授权确认
- 结果：是否值得继续收集视觉样本的 Gate 表
- 参考：`03-AI数据与评测工作包_v1.0.md` 第 2 节

这三个任务可以同时开始，但 RPT-00 的最终决策必须由负责人确认，不能由 AI 自行冻结。

## 2. SYS-00 完成后派发

### 任务 4：SYS-01 统一质量门禁

- 分支：`chore/sys-01-quality-gate`
- 独占：`package.json` 和新增质量工作流
- 可并行：SYS-02
- 不得接触生产密钥和生产数据

### 任务 5：SYS-02 生产监控、备份与恢复值守

- 分支：`ops/sys-02-production-readiness`
- 独占：新增 Gate6 工具和运行手册
- 可并行：SYS-01
- 默认只做只读检查；恢复只在隔离环境验证

### 任务 6：SYS-03 手机端关键路径

- 分支：`fix/sys-03-mobile-critical-path`
- 启动条件：SYS-00 已产出可复现的 P1/P2 手机问题
- 独占：公共布局、全局 CSS 和被选中的页面组件
- 不建议与 RPT-05/RPT-06 同时执行
- 只修证据明确的问题，不进行全站主观改版

## 3. RPT-00 确认后派发

### 任务 7：RPT-01 赛果状态机与纯函数

- 分支：`feat/rpt-01-result-state-machine`
- 独占：赛程领域核心文件
- 必须先于所有裁判报分 API 和 UI
- 不修改页面、不接数据库、不接 AI

### 任务 8：RPT-02 裁判身份与比赛分配

- 分支：`feat/rpt-02-referee-auth`
- 启动条件：RPT-00 身份方案已确认
- 独占：`src/proxy.ts` 和裁判鉴权文件
- 可与 RPT-03 并行

### 任务 9：RPT-03 私有比赛凭证存储

- 分支：`feat/rpt-03-private-evidence`
- 启动条件：RPT-00 保存和权限方案已确认
- 可与 RPT-02 并行
- 只新增 migration，不修改已执行 migration
- 只能在隔离环境验证

RPT-01、RPT-02、RPT-03 可以在文件所有权明确时并行；任何一个任务需要修改另一个任务的独占文件时必须停下协调。

## 4. 基础合并后串行派发

### 任务 10：RPT-04 报分和管理员处理 API

- 依赖：RPT-01、RPT-02、RPT-03 全部合并
- 分支：`feat/rpt-04-result-api`
- 只允许一个集成 AI 执行

### 任务 11：RPT-05 裁判工作台

- 依赖：RPT-04
- 分支：`feat/rpt-05-referee-workspace`
- 可与 RPT-06 并行，前提是页面和组件不重叠

### 任务 12：RPT-06 管理员异常赛果工作台

- 依赖：RPT-04
- 分支：`feat/rpt-06-admin-result-review`
- 可与 RPT-05 并行

### 任务 13：RPT-07 综合验收

- 依赖：RPT-05、RPT-06
- 分支：`test/rpt-07-result-e2e`
- 单一验收 AI 执行，不能由原开发 AI 自己宣布通过

## 5. AI 轨道派发条件

### 可以提前派发

- AIE-01 样本治理和标注规范：AIE-00 得出继续调查后；
- AIE-02 离线框架设计：样本 schema 冻结后，可先使用合成图片或 mock 输出验证框架。

### 目前禁止派发

- AIE-04 真实影子运行：必须等待 RPT-07 和 AIE-03 Go；
- AIE-05 生产预填：必须等待影子运行通过并重新立项；
- 任何网页 AI 按钮、生产模型 API、自动赛果提交或自动晋级。

## 6. 推荐的前五个实际指令

负责人按以下顺序创建任务即可：

1. “执行 SYS-00，只做基线和问题台账，不改代码。”
2. “执行 RPT-00，只输出裁判报分 ADR，十项产品决策留给负责人确认。”
3. “执行 AIE-00，只准备访谈、耗时和样本登记模板，不运行模型。”
4. SYS-00 完成后：“执行 SYS-01，建立统一 PR 质量门禁。”
5. 同时：“执行 SYS-02，将 Gate6 证据整理成比赛日监控、备份和恢复清单。”

每个任务都应附上 `04-多AI协作与验收规范_v1.0.md` 中的开发 AI 模板。

## 7. 负责人决策点

在以下位置必须停下来由彭杰决定：

- RPT-00：裁判身份、生效条件、强制复核和恢复边界；
- AIE-00：报分是否真的是值得投入的问题；
- RPT-07：是否允许裁判报分功能进入生产；
- AIE-03：离线模型是否达到 Gate；
- AIE-04：是否允许真实赛事影子运行；
- AIE-05：是否单独立项生产 AI 预填。
