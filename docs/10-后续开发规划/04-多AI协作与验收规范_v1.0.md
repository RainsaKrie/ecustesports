# 多 AI 协作与验收规范 v1.0

- 目标：让多个 AI 在同一项目上工作时保持范围清晰、文件隔离、证据一致和可安全合并
- 适用对象：开发 AI、审查 AI、集成负责人和发布负责人
- 核心原则：一项任务一个分支，一个高冲突区一个负责人，开发与审查分离，生产发布单点负责

## 1. 角色分工

### 项目协调人

- 选择当前波次和工作包；
- 确认依赖已经完成；
- 分配高冲突文件所有权；
- 决定是否接受范围变化；
- 更新计划和决策日志。

### 开发 AI

- 只完成一个工作包；
- 先读项目规则和专项计划；
- 在独立分支或 worktree 工作；
- 编写测试并运行质量门禁；
- 输出交付报告；
- 不自行合并或部署生产。

### 审查 AI

- 只读检查目标分支相对基线的 diff；
- 验证业务正确性、安全、并发、恢复和测试质量；
- 不顺手重构或添加功能；
- 给出阻塞项和非阻塞建议；
- 审查通过不等于产品负责人验收。

### 集成负责人

- 按总计划顺序合并；
- 解决跨工作包冲突；
- 运行完整质量门禁；
- 验证功能开关默认关闭；
- 维护主分支稳定。

### 发布负责人

- 管理 Vercel、Supabase、域名和生产密钥；
- 执行生产迁移、备份、发布和回滚；
- 开发 AI 不兼任发布负责人，除非得到明确授权。

## 2. 开始任务前检查

- [ ] 已指定唯一工作包 ID；
- [ ] 已确认依赖工作包完成；
- [ ] 已从最新 `origin/main` 创建独立分支或 worktree；
- [ ] 工作区没有来源不明的未提交修改；
- [ ] 已阅读根目录 `AGENTS.md`；
- [ ] 涉及 Next.js 时已阅读本项目 `node_modules/next/dist/docs/` 的相关版本文档；
- [ ] 已阅读总计划和对应专项工作包；
- [ ] 已列出允许和禁止修改的文件；
- [ ] 已确认不会操作生产数据或密钥；
- [ ] 已指定审查者和合并顺序。

## 5. 可直接交给审查 AI 的模板

```text
你是工作包 [ID] 的独立审查者，不负责继续开发。

请以最新 origin/main 为基线，只读审查分支 [分支名/提交哈希] 的完整 diff。

必须阅读：
- AGENTS.md
- docs/10-后续开发规划/00-三轨开发总计划_v1.0.md
- [对应专项工作包文档]
- [冻结的 ADR/接口合同]

重点检查：
1. 是否完成工作包目标且没有扩大范围；
2. 是否修改了禁止文件或覆盖用户已有修改；
3. 服务端身份、权限、输入、限流、幂等、并发和审计是否成立；
4. 状态失败时是否会出现半更新、双重晋级或静默覆盖；
5. 恢复与回滚是否真实可行；
6. 测试是否覆盖正常、异常、越权、重复和并发路径；
7. 是否包含密钥、个人信息或真实生产数据；
8. UI 是否在手机端可完成任务，而不只是没有溢出；
9. 功能开关是否在服务端生效并默认关闭；
10. 文档与实现是否一致。

输出格式：
- 阻塞问题：按严重度列出文件、位置、后果和修复建议；
- 非阻塞建议：可后置项；
- 测试缺口；
- 是否建议合并：是 / 修复后再审 / 否；
- 不要直接修改代码或执行生产操作。
```

## 8. 合并前检查

- [ ] 开发 AI 已提交交付报告；
- [ ] 独立审查没有未解决阻塞问题；
- [ ] 分支已基于最新主分支处理冲突；
- [ ] 高冲突文件只有一个任务来源；
- [ ] 完整质量门禁通过；
- [ ] 新迁移只在隔离环境验证；
- [ ] 环境变量只记录名称和用途，不记录值；
- [ ] 功能开关默认关闭；
- [ ] 旧路径和手工回退仍然可用；
- [ ] 文档和代码一致；
- [ ] 没有无关格式化、依赖升级或资源删除；
- [ ] 回滚提交和影响范围明确。

## 9. 发布前检查

发布不等于合并。发布负责人还需要确认：

- [ ] 已备份当前生产数据；
- [ ] migration 在隔离环境验证；
- [ ] 生产环境变量已经由负责人配置；
- [ ] 发布前后健康检查通过；
- [ ] 关键页面和写流程完成最小烟雾验证；
- [ ] 功能开关按批准范围开启；
- [ ] 可以在不回滚数据库的情况下关闭新入口；
- [ ] 监控和告警接收人在线；
- [ ] 回滚方式已准备；
- [ ] 发布记录已写入版本记录。

## 10. 多 AI 常见失败与处理

### 同时修改同一核心文件

停止较晚开始的任务，先合并文件所有者的工作，再重新派发。不要让两个 AI 各自解决冲突后同时提交。

### 一个 AI 擅自扩大范围

拒绝整个混合提交或要求拆分。不能因为其中包含有用修改就接受无法审查的大包。

### 测试通过但产品流程错误

回到冻结的状态机、权限矩阵和任务脚本检查。自动化通过只说明已有断言通过，不代表需求正确。

### AI 声称已部署或已操作生产

要求提供可核验证据，并立即检查生产审计；未授权生产操作按高风险事件处理。

### 文档和代码相互冲突

由项目协调人确认哪个是已批准决策。执行 AI 不自行选择更方便实现的一方。

### 模型演示效果好但没有评测

保持生产 AI 开关关闭，返回 AIE-01～03。单张截图成功不能作为上线证据。

## 11. 工作终止条件

执行 AI 遇到以下任一情况应停止，而不是继续猜测：

- 需要产品负责人选择新的业务规则；
- 需要真实生产密钥或扩大生产权限；
- 需要清空、重置或迁移真实赛事数据；
- 当前分支包含无法区分来源的未提交修改；
- 依赖工作包尚未合并；
- 高冲突文件已被另一工作包认领；
- 测试揭示现有生产路径存在 P0 数据错误；
- 实现要求违反 AI 不自动提交或不接触生产的边界。
