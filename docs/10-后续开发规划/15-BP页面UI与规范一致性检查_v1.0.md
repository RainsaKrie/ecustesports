## 二、发现的问题

### ★★★ P1-1：已完成 BP 无法回溯（影响界面 + 数据可见性两处）

**现象**：M14（已完成）页面只有一句「BP 完成！比赛地图：莲华古城」，
**流程条、地图网格、操作记录（6 次 Ban 记录）全部不显示**。

**根因**：`src/app/bp/[id]/page.tsx` 行 241
```tsx
{session && session.status === "进行中" && (
  <>
    ...当前提示、地图网格、流程条（行317）、操作记录（行356）
```
整个内容块被包在「进行中」条件里 → 完成后全部消失。

**与规范冲突**：`BP页面设计_v0.1.md` §2.5 明确要求
「下方**保留完整记录供回溯**」「已完成的会话不再可操作」——
是"不可操作"而不是"不可见"。

**★ 叠加问题**：列表页 `src/app/bp/page.tsx` 行 47 只筛 `status === "已排期"` 的比赛
```tsx
const bpMatches = state.matches.filter((m) => m.status === "已排期" && ...)
```
→ **5 场已完成的 BP 在列表里全部看不见**。

**合并后果**：赛后完全无法通过界面回溯任何一场 BP 的 Ban/Pick 过程。
赛场出现争议（"当时到底禁了哪张图"）时没有可查的界面证据。

**建议**：完成态保留只读的流程条 + 记录（把"进行中"的条件拆开，操作按钮按状态禁用即可）；
列表页增加已完成 BP 的展示（或加筛选）。

### ★★ P1-2：副标题文案重复，16 场受影响

**现象**：房间页顶部显示「**入围赛 · 入围赛** · BO1 · 地图池 7 张」。

**根因**：行 162 `{match.phase} · {match.round} · {match.boType} · 地图池 N 张`，
而入围赛比赛的 `phase` 与 `round` 两个字段**值相同**。

**核实数据**：`schedule.json` 里 **16 场入围赛全部是 `phase="入围赛"` + `round="入围赛"`**；
其余（小组赛/淘汰赛）两个字段不同，显示正常。
→ 影响 50 场里的 16 场（32%）。

**建议**：两字段相同时只显示一次。

### ★★ P2-1：列表页「BP 规则」把 BO3 顺序当通例

**现象**：`/bp` 顶部固定显示「A禁 → B禁 → A禁 → B禁 → A选 → B选 → 决胜图」，
**写死在代码里**（行 60 的数组），但紧随其后的说明文字同时讲了三种 BO。

**为什么是问题**：那条顺序只对 BO3（池 7 张）成立。BO1 是 6 个 ban、无 pick、无决胜图；
BO5 是 2 个 ban + 5 个 pick、无决胜图。**用户看 BO1 的规则条会误解**。

**建议**：改为「按当前赛制动态」或标注「以 BO3 为例」。

### ★★★ P2-2：先手配色有两个逻辑 bug（不只是「用了令牌外的蓝色」）

**初查时我把它记为「引入了令牌外蓝色」——修复时逐状态枚举才发现是逻辑 bug。**

**bug 1：两个队伍点永远同色。**
行 204 与 212 的判定互相矛盾（红蓝在两侧对调）：
| `firstTeamSide` | A 侧点 | B 侧点 | 结果 |
|---|---|---|---|
| `"A"` | 红 | 红 | ★ 同色 |
| `"B"` | 蓝 | 蓝 | ★ 同色 |
两个点**总是同色**，无法区分哪队是哪队。

**bug 2：同一个「先手」状态在两侧颜色不一致。**

| 谁先手 | A 侧卡片高亮 | B 侧卡片高亮 |
|---|---|---|
| A 先手 | **红** | 灰 |
| B 先手 | 灰 | **蓝** |

→ 用户看到红框以为是"这个队伍特殊"，而红只在 A 先手时出现。

**bug 3（规范问题）**：那个蓝 `#4f8ef7` 不在设计令牌内，
违反 UI 规格 §八「不采用四栏描述的色值，保持现有令牌」。

**本质**：用「颜色」同时承担了**两个语义**（队伍身份 + 先手），互相打架。
列表页的用法其实是对的（红=A 队、蓝=B 队，只表示身份）。

**修复（已改）**：
- **点位色 = 队伍身份**（A=`#ff4655` 品牌红、B=`#25313b` `--ink-soft` 深墨），**与列表页统一**
- **卡片高亮 = 先手**（统一用品牌红，不再 A 红 B 蓝）
- 「先手」另有黄色 Badge 标识，文字层不依赖颜色
- 蓝色彻底移除（列表页 B 侧也一并改为深墨）


### P2-3：颜色体系与全站其它部分不一致（漂移）

**实测对比**：

| 页面 | 主色系 | 语义色 |
|---|---|---|
| **BP 列表 / 房间** | `gray-*`（15 个类） | `red/green/yellow/emerald/amber`（27 个类） |
| 后台工作台 | `slate-*`（17 个类） | 少量 |

BP 用 Tailwind `gray`，后台用 `slate`，两者是不同灰系。
虽然规范只硬性要求「禁圆角 + 用令牌色 + 后台不引入新配色」，
但 BP 房间大量使用 Tailwind 调色板（19 个类）与全站令牌体系并行，属**视觉语言分裂**。

**说明**：BP 房间是深色场景，规范说「深色底沿用 #0f1923 风格」，
有一定自由度。这条**优先级低于前四条**，属打磨项。

### P3：两处字号偏小

| 位置 | 实测 | 说明 |
|---|---|---|
| 「先手」徽章（`bg-yellow-500 text-black`） | 桌面 14px / **移动 9.3px** | 房间页关键状态标识，移动端 9.3px 偏小；且用 Tailwind 黄，非令牌语义色 |
| 副标题「入围赛 · 入围赛…」 | 14px | 次要信息，可接受 |

### P3：移动端触控目标不足（**主因在页脚，非 BP 本身**）

实测移动端 7 个元素 < 44px：**5 个来自全站页脚导航**（赛事/公告/社群/工具/工作台）、
1 个是页脚品牌 logo、1 个是 BP 自己的「← BP 列表」（退出键 **92×34**）。

**BP 自身只有 1 处**（退出键高度 34px）。房间页在地图上没有触控问题（地图卡片是 `aspect-video` 大块）。

## 三、顺带发现：`mono-label` 未定义（已修）

`mono-label` 在**裁判工作台用了 23 处，但全仓没有定义** —— 这 23 处
丢失了 mono 字体、字距与大写样式（只剩调用处显式传入的颜色）。

**修复（2026-09-17，同一批）**：在 `globals.css` 补齐定义。取舍如下：

| 决定 | 理由 |
|---|---|
| 字距取 **0.05em**，而非 `.section-kicker` 的 0.2em | 23 处里**有 13 处是中文**（「裁判凭证」「我的比赛」「系统判定胜者」…）。中文加宽字距会明显松散，而裁判工作台以手机为主，宽字距还挤占本就很窄的行宽 |
| **不锁定 `font-size` / `font-weight`** | 调用处既有 `<h2>` 标题（「我的比赛 · N」）也有次级元信息（「A 胜局」），统一字号会抹平层级 |
| **不锁定 `color`** | 颜色由调用处按语义显式传入（红/墨/灰/绿） |
| 保留 `uppercase` | 对中文无影响，对 `MATCH 01` / `SUBMITTED` 等英文标签生效 |

**实测验证**：登录页 3 处 + 裁判端 8 处，均生效
（`Geist Mono` / `letter-spacing: 0.8px` / `text-transform: uppercase`），
中英文混排观感正常、无横向溢出；圆角仍为 0。

> 注：这与 BP 无关（BP 没用这个类），但因为同一批修复一起做，故记在此。

## 六、检查方法与边界（供复用）

**怎么查的**
1. 先定基准：`UI设计规格_v0.1.md`（已确认）+ `BP页面设计_v0.1.md`（草案）——
   **没有基准就无法判断"是否一致"**，这一步不能跳。
2. 静态读代码定位疑点（圆角、色值、字号、断点）。
3. **真实浏览器实测**：桌面 1440×900 + 移动 390×844，注入探针量
   （`getComputedStyle` 取 borderRadius / fontSize / backgroundColor、`scrollWidth` 判溢出、
   遍历元素找 < 44px 触控目标）。
4. 截图人工确认（数值对 ≠ 看起来对）。

**关键：用「实测」而不是「读代码」下结论的例子**
- 「BP 页面字号是否过大」——实测发现 14px 的字**全部来自全站页脚**，不是 BP 页面 → 避免误报。
- 「触控目标是否合格」——实测 7 个不足 44px 的元素里 **5 个来自页脚**，BP 自身只有 1 个 → 缩小了范围。
- 「完成态是否真的没有记录」——静态读代码看到流程条与记录**代码里都有**，
  但实测发现它们被包在「进行中」条件下、完成态不渲染 → **只读代码会漏掉这个 bug**。

**本次未覆盖**
- BP **进行中**状态的界面（本地 5 场 BP 全部已完成，没有进行中的会话可看；
  要造一个需要改数据，未做）。
- 队长 / 裁判**登录后**的界面（需要凭证）。
- 真机（本次是 headless 视口模拟）。
