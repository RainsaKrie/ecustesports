# QQ / 微信接入规划 v0.1（讨论稿）

> 2026-10-19，负责人提出「接入 QQ/微信，比如公众号、机器人，或者平台内展示微信/QQ 相关内容」。
> **本稿只做三件事**：拆清三种接入形态、判断哪种对本平台真正有用、列出需要负责人提供的东西。

## 一、先分清三种"接入"

| 形态 | 是什么 | 用户在哪一侧 | 门槛 |
|---|---|---|---|
| **A. 平台内展示** | 网站显示 QQ 群号 / 微信群二维码 / 客服号 | 他已经在网站上 | **零门槛**，改页面即可 |
| **B. 群机器人推送** | 赛程变更、开赛提醒、赛果自动发到 QQ 群 / 企业微信群 | 他在群里 | 需要群机器人 Webhook；**QQ 群机器人目前权限收紧** |
| **C. 公众号** | 赛事公告推文、菜单跳转网站 | 他在微信里 | **需要认证主体**（学校社团通常要挂靠）；订阅号不能主动推送 |
| **D. 微信个人号机器人** | 自动应答 | 他在微信里 | **违规，不做** |

## 二、对本平台真正有用的顺序

**① A（展示）—— 立刻可做，收益确定。**
现状已经有 QQ 群号（`1107657580`），但没有二维码、没有「怎么进群」的说明。
→ 赛事页放群二维码 + 一句「有问题进群问」；参赛管理页放"联系主办方"。

**② B（群机器人推送）—— 收益最大，但要看平台限制。**
办赛者真正的痛点是「改了赛程要一个个通知」和「赛果要手动发群」。
→ 推送内容优先级：**赛程变更通知 > 开赛前 1 小时提醒 > 赛果摘要 > 每日赛程**。
→ 难点：QQ 群机器人（`go-cqhttp` 类）2023 年后大幅收紧；**企业微信群机器人**反而稳定且有官方 Webhook。
→ **需要负责人确认**：赛事群是 QQ 群还是微信群？如果主要在 QQ 群，B 的可行性要重新评估。

**③ C（公众号）—— 发布公告用，不解决实时问题。**
→ 只适合赛前公告、赛后战报这类**不要求实时**的内容。
→ 门槛在**认证主体**，不在技术。

## 三、如果做，最小的技术形态

**统一成一个"通知出口"抽象**，避免散在各处：

```
domains/notify/
  ports.ts        出口接口：send({ channel: "qq-group" | "wecom-bot" | "wecom-app", title, body, url })
  adapters/
    wecom-bot.ts  企业微信群机器人（最简单，一个 Webhook URL）
    qq-group.ts   QQ 群机器人（视权限而定）
  templates.ts    文案模板：赛程变更 / 开赛提醒 / 赛果
```

**关键设计**：所有通知**从 L2 用例触发**（改期、报分、阶段推进），
而不是散落在各个路由里 —— 否则又会出现"同一个通知三处写"。

## 四、需要负责人提供

1. **主群在 QQ 还是微信**（决定 B 走哪条路）；
2. 群机器人是否已有（企业微信群 → 群设置里直接拿 Webhook；QQ 群看是否有管理权限）；
3. 公众号有没有可用主体（学校/社团能否认证）；
4. 通知**发给谁**：只发群，还是也要私聊队长。

## 五、不建议现在做

- **公众号**：认证周期长，且不解决实时问题；
- **微信个人号机器人**：违反平台规则，账号风险不可控；
- **双向交互**（在群里查赛程）：需要常驻服务 + 长连接，校园赛规模不值当。

**建议顺序**：先做 A（一天），再评估 B（看主群在哪），C 放到赛后。
