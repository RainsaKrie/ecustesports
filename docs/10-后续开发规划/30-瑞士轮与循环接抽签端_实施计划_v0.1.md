> **本稿只列实施步骤与风险。**
>
> **进展（2026-10-19 晚）**：第 1、2、4 步已完成（729622a，43 套 / 新增 11 条断言全绿）。
> **第 3 步（抽签页 UI）未完成** —— 后端链路全通（判定→构建→分派→保存），
> 但页面上还没有「生成第 1 轮」的入口：现有抽签流依赖抽签盘（），而瑞士轮/循环不需要抽签。 引擎与规则已完成（见 `27`、`stage-chain-rules`）。

## 一、为什么不能只改一半

现在保存接口会拒绝 `swiss` / `round-robin`，理由正是**抽签端只认 5 种结构**。
如果只把这两种加进 `resolveSupportedFormat` 而不同时接抽签端，就会**重新制造"能存不能抽"**
—— 那是我今天刚修掉的 bug（`af77607`）。

**所以这两件事必须同一个提交完成**：格式判定 + 抽签生成。

## 二、改动清单（按依赖顺序）

### 第 1 步：`format-support.ts` 加两个 kind

```ts
| { kind: "swiss"; stage: StageConfig; requiredTeams: number }        // 单段、2 的幂、≥8
| { kind: "round-robin"; stage: StageConfig; requiredTeams: number }  // 单段、3–6 队
```

判定条件（与 `stage-chain-rules` 的 R4/R5 同口径，**不要另写一套**）。

### 第 2 步：`buildTournamentMatches` 接分派

- **swiss**：**只生成第 1 轮**（`pairSwissRound(ids, 空状态, 0)` = 相邻配对）。
  后续轮次依赖战绩，**由报分后逐轮生成**，不在抽签时算。
- **round-robin**：`buildRoundRobinRounds(ids)` → 展开成平铺场次（或按轮次编排）。

两处都**复用已有引擎**，不重写。

### 第 3 步：抽签页（`FormatDrawWorkspace.tsx`）加分支

这两个格式**不需要"抽签"这个动作** —— 第 1 轮是按种子顺序直接配的。
→ 抽签页对它们显示「生成第一轮」，不显示分组/抽签盘。
→ **注意**：该文件 948 行，有 4 处按 `format.kind` 分支（`:328 / :349 / :364 / :409`），
   每处都要确认新 kind 走哪条路，**不能只改一处**。

### 第 4 步：测试

- 每个新 kind 一条：能判定、能生成、场次数正确；
- **回归**：现有 7 套模板的判定结果不变；
- **变异验证**：故意把 swiss 的队数判定放宽，测试必须变红。

## 三、风险

| 风险 | 说明 | 对策 |
|---|---|---|
| **分支遗漏** | 抽签页 4 处 `kind` 判断，漏一处就是运行时"点了没反应" | 逐处枚举，改完 grep 一遍 `format.kind` |
| **瑞士轮的"逐轮"语义** | 抽签只出第 1 轮，后续要等报分 —— 办赛者可能以为抽完就有全部赛程 | 抽签页明确写「首轮已生成，后续每轮在报分后生成」 |
| **排期** | 循环赛的场次要按轮次分布，不能一坨 | 复用现有 `withPendingSlots` / 排期逻辑 |
| **保存与抽签不同步** | 保存放行了、抽签没接 → "能存不能抽" | 两者同一个提交 |

## 四、验收

1. 自定义赛制里选「16 队 · 瑞士轮 + 单败」，**保存成功**；
2. 抽签页显示「生成第一轮」，点击后**首轮 8 场**正确生成；
3. 报分一轮后，**第 2 轮按战绩配对**且无重赛；
4. 现有 7 套模板的抽签流程**行为不变**（回归）；
5. 门禁 EXIT=0，42 套（+ 新增）全绿。
