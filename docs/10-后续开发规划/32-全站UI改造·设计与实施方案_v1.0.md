## 0. 一页速览

**结论五条**

1. **全站已经是暗的，但只有赛程页是「v8 的」**。`body.pub-dark` 早已全站生效，公开面 30 个页面里只有 `PublicSchedule` 按 v8 结构重排过；`.pub-card` / `.pub-frame` 两个卡片类**定义后 0 处使用**，全仓 `backdrop-filter` 使用 **0 次**，海报底只挂在赛事详情 1 页 —— 即「换了底色，没换语言」。
2. **当前有 20+ 处可读性事故，属于线上缺陷，不是审美问题**。批量换暗（`935d498`，15 文件 / 329 处）留下了白底白字（1.0:1）、浅底白字（1.01–1.05:1）、以及 `RefereeWorkbench` 34 处 `text-[#0f1923]` 落在玻璃卡上（≈1.01:1）。**这必须先修，和"好不好看"无关。**
3. **这件事的本质是「建三层，再逐页换」**：令牌层 → 原件层（6 个 v8 范式固化成类）→ 版式层。若跳过原件层逐页改，31 个页面会各写一遍内联 Tailwind，最终得到第二份 `globals.css` —— `pub-theme.css` 已经显露出这个趋势。
4. **最大工程约束不是审美，是守卫**：`globals.css` 被锁成「只许变短」（基线 1966 行）；新文件 >400 行即红；页面 >300 行即红；TSX 里写新 hex 会红；Tailwind 命名色绝对红线。**但守卫存在致命盲区**：对比度只查 4 个 `--adm-*` 令牌 × 3 底色，`--pub-*` 完全不查，非文本 3:1 根本没实现 —— 也就是「守卫全绿 ≠ 页面读得清」。
5. **后台不是"没设计"，是另一套已成立的工具语言**（平、密、无玻璃、无折线、4 个强调色）。要把两套合成一套，推荐**路线 B：换令牌 + 补卡片语言 + 补表格行语言**，不动布局。照抄公开面版式（路线 C）会直接破坏后台密度。

## 1. 任务定义与边界

### 1.1 「把 UI 换成 v8 风格」拆成三层

| 层 | 内容 | 判定标准 | 本方案手段 |
|---|---|---|---|
| L1 皮肤 | 底色、框线、文字层级、强调色、字体、间距、圆角=0 | 全站只出现 1 个页面底色、1 个强调色、1 套文字三层 | 令牌（唯一真源） |
| L2 原件 | 卡片、按钮、标签、输入、弹窗、表格行、空态、骨架、Toast | 同类控件在不同页面**长得一样**、只有一处实现 | CSS 组件类 + 少量 React 原语 |
| L3 版式 | 页头、Hero、数字条、阶段条、分区标题、六列行 | 同类信息**排布结构一致**、窄屏退化规则一致 | 6 个 v8 范式类 + 页面骨架 |

doc 31 的 5 个批次是**按页面分的**，本方案改成**按层分**，理由：按页面分会让每个页面都重复实现一次 L2，工作量随页面数线性增长且必然漂移（这正是 `26-守卫与巡检梳理` 说的"同一种事实两处维护"）。

### 1.2 不做什么

- 不动业务逻辑、数据接口、路由、服务端行为（只改表现层）。
- 不新增图标库（v8 只有 `＋` 与折线；沿用现有 `→ ← ＋ ⋯ ×`）。
- 不引入 UI 框架、不换 Tailwind 版本、不引入 CSS-in-JS。
- 不重命名业务组件与文件路径（避免架构守卫 ③④⑤ 与路径字符串读取型测试连带改动）。
- 不做深色/浅色双主题切换（v8 是唯一目标形态，双主题会让令牌翻倍）。

### 1.3 需要修正 doc 31 的三处

| # | doc 31 说法 | 实际 | 修正 |
|---|---|---|---|
| 1 | 第 4 批含「兼容跳转页」 | `/[game]` **不是跳转页**（`src/app/[game]/page.tsx:11-13` 渲染浅色 legacy 的 `GameLanding`）；真正跳转的是 `/schedule`、`/bracket`、`/market` 三个 8 行 redirect | `/[game]` 单列一项待拍板；三个 redirect 不需要任何 UI 工作 |
| 2 | 公共层 `Container` 对齐「1100px / 28px」 | v8 实际是 `max-width:1080px; padding:28px 24px 64px`（v8:34）；现实现 `max-w-7xl`=1280px，`pub-theme.css:103-106` 已把页头改成 1100/28 | **基准内部不一致**，必须二选一，见 §8-④ |
| 3 | 管理端 13 页 | 14 个 `page.tsx` 里 **5 个是 redirect 空壳**，真正要改 UI 的后台页面只有 **9 个**，真正的工作量在 `src/components/admin/` 的 22 个组件（5,452 行） | 按组件排工，不按页面 |

## 2. 基准解构：把 v8 变成可执行值

### 2.1 令牌表（唯一真源 → `globals.css :root`）

| 类别 | 令牌 | v8 原值 | 落地值 | 用在哪 |
|---|---|---|---|---|
| 底色 | `--bg` | `#0d0f12`（v8:6） | **`#0a0b0d`**（公开面已上线，不引入第 8 个近黑） | 页面底 |
| 卡片 | `--surface` | `rgba(255,255,255,.055)` | `rgba(255,255,255,.05)` | 玻璃卡底 |
| | `--surface-solid` | — | `rgba(255,255,255,.055)` | 窄屏/不支持 blur 的降级 |
| 线 | `--line` | 22%（doc 31 §一-3） | `rgba(255,255,255,.22)` | 结构线、分组框 |
| | `--line-soft` | 14% | `rgba(255,255,255,.14)` | 卡片框、表格行线 |
| 文字 | `--text` | `#f2f3f5`（17.7:1） | 同 | 正文 |
| | `--text-soft` | 62% | **64%**（与已上线公开面一致） | 次要 |
| | `--text-mute` | 52%（5.26:1 过 AA） | 52% | 灰字/表头 |
| 强调 | `--red` | `#ff4655` | 同 | 唯一强调色 |
| | `--red-deep` | — | `#c83242` | 仅用于**线/描边**（文字用 `#ff4655`；`#c83242` 在深底只有 3.65:1，不可做正文） |
| 记号 | `--mark` | 折线 9/13/7px、网格 88px | 折线 **10px**、网格 **56px**（已上线） | 折角/网格 |
| 圆角 | — | 0（全篇） | **0，写进规范防回退** | — |
| 字体 | sans / mono | `system-ui` + 系统 mono | 沿用 `Geist + CJK 回退`（不换字体） | 数字用 mono，中文不用 |
| 字号 | — | 10.5 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14.5 / 15 / 16 / 18 / 19 / 26 / 30 / clamp(34,5.2vw,58) | 补 **10.5 / 11.5** 两档（现缺），其余用 `--fs-*` | — |
| 间距 | — | 区块 24–42；卡内 12–18；列表间距 6 | 新增 `--sp-section:32`、`--sp-card:16`、`--sp-row:6` | — |
| 动效 | 时长/曲线 | 140ms 颜色/边框 | 沿用 `--dur-fast/--ease-standard` | — |

> **v8 有 12 处引用 `var(--line)` / `var(--line-soft)`，但 `:root` 从未定义**（v8:6 只定义了 `--card-line`）。照抄会得到"没有边框的卡片"。**一律以上表的 22% / 14% 为准，不要逐字搬 v8 变量名。**

### 2.2 六个范式 → 六个类（本方案的核心杠杆）

v8 的信息设计可以压成 6 个可复用结构。把它们固化成 CSS 类后，页面改造从「重写 JSX + 内联 Tailwind」变成「套类名 + 填数据」，工作量从**按页线性**变成**按范式常数**。

| # | 范式 | 类名 | v8 出处 | 结构 |
|---|---|---|---|---|
| ① | 页头 | `.ui-top` | v8:37-44 | 左品牌（红色折角 mark + 名称）/ 右导航（选中项红色下划线）；透明底 + 底部 1px 10% 线 |
| ② | Hero | `.ui-hero` | v8:47-55 | mono 眉标（红、字距 .22em）→ clamp 大标题（红句号）→ 一句副标题（≤52ch） |
| ③ | 数字条 | `.ui-stats` | v8:58-63 | 上下 22% 线、竖线分隔、等宽数字、重点数字红；**不用卡片** |
| ④ | 阶段条 | `.ui-stages` | v8:66-91 | 4 列切角卡；done/now 两态；底部进度底线（红/灰各半）；now 态左 2px 红条 + 右上切角 |
| ⑤ | 分区标题 | `.ui-sec` | v8:124-126 | 左标题 18px/800 + 右 mono 11.5px 注记；底部 **2px 红实线** |
| ⑥ | 数据行 | `.ui-row` / `.ui-thead` | v8:117-156 | 六列固定 `84px 1fr 1fr 88px 1fr 92px`；左红条 hover、右上折角、赢方红比分 + 5px 红点；≤760 退化 4 列 |

配套装饰类：`.ui-frame`（玻璃卡 + 1px 14% + 左上红折线/右下灰折线）、`.ui-tag`（mono 10.5px、1px 线、透明底）、`.ui-toggle`（v8 `.gtabs` 分段控件）。

**注意**：`.pub-frame` 已在 `pub-theme.css:65-94` 定义但 **0 处使用**；本次要么把它改名为 `.ui-frame` 并真正铺开，要么删掉 —— **不能两份都留**。

| # | 坑 | 证据 | 处理 |

| 1 | `--line` / `--line-soft` 未定义 | v8:4-10 vs 引用 12 次 | 用 §2.1 的 22%/14% |
| 2 | `.stats` 定义两遍（后者覆盖前者） | v8:52-55 与 v8:58-63 | 取第二版（竖线分隔、无卡片） |
| 3 | `.glass` / `.thead` 是死类（markup 0 处使用） | v8:33、v8:117-122 | 不引用；玻璃写在 `.ui-frame` |
| 4 | 容器宽度自相矛盾 | v8:34 `1080/24` vs doc 31:32 `1100/28` vs 现实现 `1280` | 见 §8-④ |

### 2.4 基准没有的 4 类控件（必须新定规格，否则各写各的）

| 类 | 规格（可直接实现） |
|---|---|
| **输入 / 下拉 / 文本域** | 高 44（md）/ 32（sm）；底 `rgba(255,255,255,.04)`；1px 14% 线；文字 15px；placeholder 52%；focus 边框转红 + 2px 红 outline（offset 2，全局规则已有） |

## 3. 目标架构

### 3.1 CSS 文件职责与行数预算（守卫驱动）

| 文件 | 现状 | 预算 | 职责 |
|---|---:|---:|---|
| `src/app/globals.css` | **1966（锁定只许变短）** | 先删 ≈388 行死类 → 再在 `:root` 加令牌 | **唯一令牌真源**（色板与对比度守卫都只读这里）+ `@theme` + 全局 html/body + 后台 `.adm-*` 组件类 |
| `src/app/pub-theme.css` | 170 | ≤400（余 230） | 公开面作用域：`.pub-dark` 令牌、海报底、站头站脚覆盖、**6 个 `.ui-*` 范式类** |
| `src/app/admin-theme.css`（新建） | 0 | ≤400 | 后台：`.adm-panel`（玻璃+折线）、`.adm-row`、`.adm-input`、`.adm-micro`、表格/批量条 |
| TSX 内联 | 大量 | 只减不增 | 只写布局与内容，不写颜色/尺寸字面量 |

**三条铁律**

1. **新颜色只能进 `globals.css :root`**（色板从那里现算）。写进 TSX 的新 hex → color-guard 红；写进新 CSS 文件 → 不进色板但不触发守卫（可以，但会被视为"色板外"，后续维护不可查）。
2. **`globals.css` 任何净增行都会红**（arch ①b）。所以顺序必须是**先删 28 个死类腾行数，再加令牌**。
3. **新文件 >400 行即红；页面 >300 行即红**。所以范式类必须拆到 `pub-theme.css` / `admin-theme.css`，不能全塞 globals。

### 3.2 令牌分层（消灭"两套色板"）

现状有 4 套：`--pub-*`（公开）、`--adm-*`（后台）、`PUBLIC_EXTRA`（守卫白名单 14 色）、以及散落在 TSX 的裸 hex。目标：

```
globals.css :root
  ├── 基础令牌（单一真源）  --bg --surface --line --text --red …
  ├── 公开面别名            --pub-bg: var(--bg)  …（保留名字，避免批量改 271 处）
  └── 管理端别名            --adm-surface: var(--surface) …（保留名字，避免批量改 .adm-* 类）
```

**关键：`--adm-*` 与 `--pub-*` 的"名字"全部保留，只把"值"指到基础令牌。** 这样：
- 130 个 `.adm-btn` 调用点、271 处 `text-[var(--pub-txt)]` 零改动即吃到统一值；
- `ui-guards` 的对比度测试（只读 globals 里带 `#hex` 的 `--adm-*`）继续有效 —— **若把令牌搬出 globals，那条检查会静默空转通过**，这是必须避免的陷阱；
- 色板不缩水，`--ink`/`--red`/`--red-dark` 等旧令牌**换肤期不许删**（TSX 里还有 75 / 132 / 23 处裸 hex 依赖它们）。

### 3.4 后台翻译：路线选择

| 维度 | A 只换令牌 | **B 令牌 + 卡片 + 表格行（推荐）** | C 照抄公开面版式 |
|---|---|---|---|
| 与 v8 相似度 | 50–60% | **85–90%** | 95%（但不可用） |
| 表格/表单/多选 | 无影响 | 小（hover 方向、行高微调） | **结构失效**（后台表格 8–15 列） |
| 改动范围 | 1–2 个 CSS | 2 个 CSS + ≈25 个 tsx 等行替换 | 全部重写 |
| 与 doc 31「不硬套六列」 | 一致 | 一致 | **冲突** |
| 工期 | 0.5–1 d | **6–10 d** | 10 d+ |

**选 B**。后台保留自己的布局密度，只对齐四件事：①同底色族 ②同玻璃卡语言 ③同框线/文字层级 ④同单一强调色。**后台不铺海报底**（一屏几十行 + 12 个弹窗，铺底收益低且 blur 掉帧），只在页头保留 2px 红条与 mono 眉标。

## 4. 施工顺序（7 个阶段）

## 5. 验收标准

### 5.1 机器可验证（每批必过）

| 检查 | 命令 | 通过条件 |
|---|---|---|
| 全量门禁 | `CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run gate` | lint 0 错 + typecheck 过 + **43 套** + build 过 |
| 结构守卫 | `npm run test:arch-guards` | 无新增超限；基线内只降不升 |
| UI 守卫 | `npm run test:ui-guards` | 4 条全过；手写尺寸文件不增 |
| 颜色守卫 | `npm run test:color-guard` | 无新增色板外色；命名色 0 |
| 变异检查 | `npm run test:guard-mutation`（**手动、干净工作区**） | 12/12（不在门禁里，改过判据/基线必须跑） |
| 构建产物抽查 | `grep` 生成的 CSS | 关键类确实生成（防 `bg-white/[0.06]/50` 这类无效类） |

### 5.2 视觉验收（守卫的盲区，必须人工）

1. **改前先存基线截图**（改了再截就没有"改前"了）；用本机 `agent-browser`（v0.27，全局可用，无需加依赖）：
   - 31 页 × 2 视口（1440×900 / 390×844）→ `.workbuddy/ui-shots-v8/<viewport>/`（已 gitignore）
   - v8 样板本身也用同一视口截图，作为对照基线
2. **逐页对照 6 个范式**：页头 / Hero / 数字条 / 阶段条 / 分区标题 / 数据行，缺一即记入清单。
3. **计算样式抽检**：`getComputedStyle` 取 `font-size / color / background-color`，按 WCAG 复算；重点正文 ≥4.5、非文本（框线、焦点环）≥3。
4. **专项清单**：`/`（米色三角是否清掉）、`/events/[id]`（海报底网格不盖正文）、`/referee`（反色失效）、`/events/[id]/manage`、`/admin/events/[id]/schedule`、`/bp/[id]`。
5. 三档视口无横向溢出；`prefers-reduced-motion` 生效；打印/投屏单独确认。

### 5.3 守卫与基线的处理原则

**优先级：改代码 > 新增令牌 > 重生成基线 > 改判据（基本不做）**

- 新颜色 → 写进 `globals.css :root`（会 +行，先从 P1 腾出预算）；**不得**写进 TSX。
- 必须改基线时：**单独提交、只含 JSON、commit message 写数量与原因**（先例 `14b3976`）。
- **禁止**：调大 400/300、往 `PUBLIC_EXTRA` 塞值、放宽命名色正则、给对比度加豁免、把令牌搬出 globals 而不通知守卫（会让对比度检查**静默空转通过**）。
- 五条"守卫绿但页面坏"的已知盲区（本次审查实证）：`--pub-*` 从不检查；rgba 令牌被跳过；非文本 3:1 未实现；`bg-white` 与 3 位 hex 不查；`.css` 文件本身不查。
