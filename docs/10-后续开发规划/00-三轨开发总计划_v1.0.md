# 三轨开发总计划 v1.0

- 文档状态：待负责人排期
- 适用代码库：`ecustesports`
- 编制日期：2026-09-06
- 负责人：彭杰
- 用途：将后续工作拆成可交给多个 AI 独立执行、审查和合并的工作包
- 重要声明：本目录只提供规划和协作框架，不表示任何功能已经开发或获准上线

## 1. 总体判断

平台当前处于“核心赛事运营 MVP 已完成、已经真实上线、生产成熟度仍需补强”的阶段。下一阶段不应继续无边界扩功能，也不应为了求职展示直接增加 AI 入口。

后续工作分为三条轨道：

| 轨道 | 建议投入 | 目标 | 当前状态 |
|---|---:|---|---|
| A. 生产系统完善 | 60% | 保证真实用户能稳定、安全地完成关键任务 | 立即执行 |
| B. 裁判报分基础设施 | 25% | 建立不依赖 AI 的裁判报分、证据、审核和恢复闭环 | 完成设计后执行 |
| C. AI 数据与评测 | 15% | 用真实证据判断截图识别是否值得接入 | 只启动调查与离线准备 |

AI 生产接入不是当前里程碑。当前允许的是需求调查、合法样本收集、标注规范和离线评测准备。

## 2. 总体目标

### 2.1 业务目标

1. 当前线上赛事主链路不因新增功能而退化。
2. 手机端能够完成报名、身份找回、组队、查看比赛和裁判报分等关键任务。
3. 高风险操作具备身份、权限、审计、版本和恢复机制。
4. 管理员从“逐场录入”转向“处理少数异常”。
5. AI 是否进入产品由业务指标和真实评测决定，而不是由模型演示决定。

### 2.2 工程目标

1. 每个工作包可以独立分支、独立验收、独立回滚。
2. 所有纯规则和状态流转优先写成可测试函数，再接 API 和 UI。
3. 任何不完整的新能力默认关闭，不影响生产路径。
4. 多个 AI 不同时修改同一核心文件。
5. 合并前必须通过统一质量门禁。

## 4. 里程碑与退出条件

### M0：冻结生产基线

退出条件：

- 主分支、生产部署和文档基线可追溯；
- 当前自动化检查全部通过；
- 高优先级线上问题形成唯一清单；
- 禁止使用真实赛事数据做破坏性测试。

### M1：生产保护层成立

退出条件：

- 普通提交不能绕过 lint、类型、核心测试和构建；
- 有最小生产烟雾检查、备份和恢复值守说明；
- 手机端关键任务有可重复回归清单；
- 高风险写操作纳入审计缺口清单。

### M2：裁判报分领域闭环成立

退出条件：

- 裁判身份、比赛分配、提交、异常、确认、修改和撤销状态已冻结；
- 正式赛果与原始提交记录分离；
- 纯函数测试覆盖合法流转、越权、重复提交、并发和恢复；
- 尚未接入 UI 和 AI 时也能完成服务层验证。

### M3：非 AI 裁判报分可用

退出条件：

- 裁判可在手机端查看被分配比赛并手工报分；
- 比赛凭证使用私有存储；
- 正常赛果可按规则生效，异常进入管理员队列；
- 错误赛果可安全处理，不静默破坏后续对阵；
- 完整手工回退成立。

### M4：AI 离线价值验证

退出条件：

- 真实、授权、脱敏并标注的评测集冻结；
- 至少完成固定表单基线与一个视觉模型方案比较；
- 产出字段准确率、拒答、延迟、成本和失败分类；
- Gate AI-2 有明确 Go / No-Go 结论。

### M5：AI 影子验证

退出条件：

- 模型不影响正式赛果；
- 真实截图表现达到离线门槛；
- 能证明理论上减少至少 50% 手工字段输入；
- 隐私、日志、成本和失败回退满足要求。

M5 通过后才单独立项生产 AI 预填，不在本总计划中默认批准。

## 6. 推荐排期波次

### 波次 0：单负责人执行

- SYS-00：冻结基线、建立唯一问题台账。
- RPT-00：冻结裁判报分领域合同。

这两项不得交给多个 AI 同时产出互相竞争的版本。

### 波次 1：最多三个 AI 并行

- AI-A：SYS-01 统一质量门禁；
- AI-B：SYS-02 生产监控、备份与恢复值守；
- AI-C：AIE-00 现状调查模板与人工基线表。

### 波次 2：控制共享文件

- AI-A：SYS-03 手机端关键路径；
- AI-B：RPT-01 赛果状态机与纯函数；
- AI-C：AIE-01 样本治理和标注规范。

SYS-03 不得修改赛程领域模型；RPT-01 不得修改公共样式和现有页面。

### 波次 3：后端基础并行

- AI-A：RPT-02 裁判身份与分配；
- AI-B：RPT-03 私有凭证存储；
- AI-C：SYS-04 高风险操作审计，但不得修改 RPT-02 正在占用的鉴权文件。

若无法保证文件隔离，SYS-04 延后。

### 波次 4：串行集成

- RPT-04 报分和审核 API；
- 完成后再并行 RPT-05 与 RPT-06；
- 最后由单一集成负责人执行 RPT-07。

### 波次 5：AI 离线验证

- AIE-02 评测框架；
- AIE-03 模型对比与决策报告；
- 只有 Go 才进入 AIE-04 影子运行。

## 7. 核心文件冲突边界

以下文件属于高冲突区，同一时刻只允许一个工作包修改：

| 文件或目录 | 主要负责人 | 约束 |
|---|---|---|
| `src/lib/scheduling/schedule-data.ts` | RPT-01 | 其他工作包只读 |
| `src/lib/scheduling/schedule-ops.ts` | RPT-01 | RPT-04 接口层不得私自改规则 |
| `src/lib/scheduling/useSchedule.ts` | RPT 集成负责人 | SYS-03 不修改业务状态 |
| `src/app/admin/events/[id]/schedule/page.tsx` | RPT-06 或集成负责人 | 不与 SYS-03 同时修改 |
| `src/proxy.ts` | RPT-02 | SYS-04 在其合并后复审 |
| `src/lib/auth.ts`、`src/lib/participant-auth.ts` | RPT-02 | 不把裁判伪装成管理员或选手 |
| `supabase/migrations/` | RPT-03 / 集成负责人 | 每项迁移使用独立新文件，禁止改已执行迁移 |
| `src/app/globals.css`、公共布局 | SYS-03 | 新功能优先局部样式，减少冲突 |
| `package.json` | SYS-01 后由集成负责人管理 | AIE-02 如需新脚本，基于最新主分支修改 |
| `docs/00-项目管理/`、`docs/10-后续开发规划/` | 项目协调人 | 执行 AI 不自行重写总计划 |

## 8. 统一质量门禁

每个代码工作包至少执行：

```text
npm run lint
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm run test:scheduling
npm run test:loop
npm run test:bp
npm run test:registration-admin
npm run test:publication
npm run test:operations
npm run test:ai-eval
npm run build
```

若工作包新增专用测试，必须同时执行并加入交付报告。浏览器任务需要提供桌面和手机视口证据，但不得用截图代替断言。

## 9. 统一完成定义

一个工作包只有同时满足以下条件才算完成：

- 目标范围内的功能、测试和文档全部交付；
- 未修改禁止范围；
- 没有真实密钥、手机号、学号、参赛码或原始截图进入 Git；
- 不依赖修改生产数据才能验收；
- 新写接口有身份、权限、输入校验、限流、并发和审计说明；
- 新状态有正常路径、失败路径、重复操作和恢复测试；
- 新 UI 在 390px 和常见桌面宽度可完成关键任务；
- 统一质量门禁通过；
- 提供变更摘要、风险、测试结果、未完成项和回滚方式；
- 由另一名 AI 或人工进行只读审查后才能合并。

## 10. 合并策略

1. 每个工作包从最新 `main` 创建独立分支，不在同一分支堆叠无关任务。
2. 执行 AI 不直接推送或合并 `main`，除非负责人明确授权。
3. 每次只合并一个高冲突工作包，合并后重新运行完整门禁。
4. 基础合同和纯函数先于 API，API 先于 UI，非 AI 闭环先于 AI。
5. 未完成能力使用服务端功能开关并默认关闭，不能只隐藏前端入口。
6. 生产部署由单一发布负责人执行；开发 AI 不操作 Vercel、Supabase 生产项目或 DNS。
7. 发生生产故障时停止合并新功能，只允许热修和恢复工作。

## 11. 负责人每周只需检查的事项

- [ ] 当前正在执行哪些工作包，是否超过并行上限；
- [ ] 是否有人同时修改高冲突文件；
- [ ] 本周合并内容是否通过完整门禁；
- [ ] 是否有未经批准的生产数据或密钥操作；
- [ ] P0 线上问题是否优先于 AI 工作；
- [ ] 裁判报分是否仍保持无 AI 可用；
- [ ] AI 工作是否仍处于当前获准阶段；
- [ ] 每个 Gate 是否有证据，而不是口头“完成”；
- [ ] 下一个合并包是否具备全部依赖；
- [ ] 是否需要更新总计划和决策日志。
