# 报名与队伍（内置方案）

- 项目：《无畏契约》校园赛事 AI 排程协同助手
- 当前版本：1.1
- 文档状态：已确认
- 日期：2026-08-17

## 1. 报名方式

网站完全内置报名，问卷星退场（或仅作为群内宣传入口，导流到网站）。

负责人提出的关键体验要求：

- 手机可扫码进入填写界面；
- 像问卷星一样便捷填写；
- 报名必须低门槛 + 好体验。

## 2. 报名体验设计（已确认）

为对齐问卷星的"扫码即填 + 低门槛"，内置报名做到以下四点：

1. **扫码即填**：负责人后台生成报名二维码，选手扫码直接进入报名表，无需先找入口。
2. **先填后绑**：不强制先注册账号；选手填完报名表、提交时绑定一个联系方式（QQ / 微信 / 手机号之一）作为后续身份，全程无"注册—登录"的繁琐步骤。
3. **手机优先（主场景）**：手机报名是主场景，报名表按手机屏幕设计（大按钮、下拉选择、即时校验提示）；电脑端仅需适配、能正常填写即可。
4. **自定义字段**：负责人可为报名表添加自定义题目（文本 / 下拉 / 单选），应对未来新需求。

## 3. 报名流程

```
选手扫码 → 填报名表 → 绑定联系方式 → 进入选手池
       → 自由组队 → 队长申报队伍 → 负责人审核 → 名单冻结
```

## 4. 选手字段

| 字段 | 必填 | 可见性 |
|---|---|---|
| 姓名 | 是 | 仅负责人 |
| 学号 | 是 | 仅负责人 |
| 游戏 ID | 是 | 公开显示 |
| 段位 | 是 | 内部（种子计算） |
| QQ | 可选 | 仅负责人 |
| 微信 | 可选 | 仅负责人 |
| 手机号 | 可选 | 仅负责人 |
| 学院 | 可选 | — |
| 自定义项 | 可选 | 负责人按需添加 |

## 5. 组队与申报

- 自由组队（沿用上届模式）。
- 队长建队，从选手池选人：**5 首发 + 1 替补（可选）+ 1 教练（可选）**。
- 队长申报 → 负责人审核 → 队伍冻结。

## 6. 身份验证

不做线下身份验证标记环节（按负责人确认）。

## 7. 决策记录（2026-08-17）

| 决策 | 结论 |
|---|---|
| 报名方式 | 内置（体验方案见第 2 节，待最终确认） |
| 选手对象 | 独立为第 10 个对象；关系简单——几个选手组成一支队伍 |
| 选手字段 | 联系方式细化为 QQ/微信/手机号（可选），学院可选，支持自定义项 |
| 身份验证 | 不做 |
| 组队方式 | 沿用上届（自由组队 + 队长申报） |

## 8. 负责人异常运营闭环（2026-08-21 补充）

负责人需要在同一报名工作台完成以下真实运营任务：

1. 对选手标记待审核、已通过、需修改或已拒绝；审核状态与是否组队分开记录。
2. 代选手更正姓名、学号、游戏 ID、段位、学院和联系方式，并填写修改原因。
3. 对已审核且未组队选手代建队伍或安排进队；队伍必须恰好有 5 名首发且所有成员审核通过，才可确认为正式名单。
4. 处理名单重新开放、换人、移出名单、个人退赛和整队退赛；队长退出或被移出时必须先指定新队长。
5. 每次负责人操作记录操作人、时间、摘要、原因和修改前后状态。只允许按时间倒序撤销最新操作，且当操作后出现玩家新报名或其他数据变化时拒绝自动撤销。
6. 约 160 人规模下支持搜索、审核状态筛选和分页；负责人无需横向滚动才能找到操作入口。

玩家自行报名、申请入队和处理邀请继续使用公开原子接口；负责人页面不得读取后自动回写整份旧状态，以免覆盖并发提交。
