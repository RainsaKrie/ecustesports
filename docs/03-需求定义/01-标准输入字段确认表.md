# 标准输入字段确认表

- 项目：《无畏契约》校园赛事 AI 排程协同助手
- 当前版本：1.0
- 文档状态：负责人已确认并冻结
- 日期：2026-08-16
- 当前范围：只定义“已发布赛程后的临时改期”所需数据，不扩展到完整报名平台

## 1. 字段设计原则

1. 排程使用队伍、比赛和裁判的匿名 ID，不需要姓名、学号、QQ、IP 等个人信息。
2. 两队先在现有渠道协商一个候选时间，系统只接收并校验该时间；首轮不建立完整可用时间日历。
3. 规则系统只接收结构化字段；自然语言必须先由 AI 解析并经提交人或负责人确认。
4. 当前有效赛程和历史版本必须分开保存，不能靠群聊中的最后一条消息判断。
5. 首轮只收集影响改期判断的字段；宣传、奖品、直播、赛后验收等信息不进入本表。

## 2. P0 数据对象

| 数据对象 | P0 必填字段 | 用途 |
|---|---|---|
| 赛事配置 | 赛事 ID、时区、阶段起止时间、允许比赛时段、默认最大并发场次 | 判断新时间是否落在赛事容量内 |
| 比赛 | 比赛 ID、阶段/轮次、参赛双方或来源占位符、BO 类型、预留时长、当前时间、状态、是否冻结、前置比赛 | 判断比赛依赖、时长和是否允许移动 |
| 队伍 | 匿名队伍 ID、队长角色 ID、当前状态 | 关联比赛、可用时间和确认责任 |
| 双方约赛时间 | 比赛 ID、候选开始时间、按 BO 类型计算的结束时间、两队确认状态、提交时间 | 表示两队已经协商出的共同时间，不要求提交完整可用时间表 |
| 裁判容量 | 时间段、该时段最大可并发比赛数、已占用场次数 | 防止约赛时间造成并发超过裁判能力；首轮不记录个人裁判日历 |
| 改期申请 | 申请 ID、比赛 ID、申请方、原因类别、原始描述、双方约赛时间、紧急程度、两队确认状态、提交时间 | 形成一次可追踪的改期任务 |
| 审批与版本 | 决策、负责人、决策时间、选中方案、拒绝/例外原因、旧版本号、新版本号 | 保证人工审批、追溯和回退 |
| 通知 | 版本号、接收角色、通知内容、生成时间、发送状态 | 避免不同对象收到互相冲突的赛程 |

## 3. 首轮明确不收集

- 姓名、学号、IP、个人 QQ 或微信。
- 所有队员的个人可用时间，以及队伍的完整可用/不可用日历；首轮只提交双方已经协商出的约赛时间。
- 每名裁判的个人可用时间和姓名；首轮只维护时段级裁判容量。
- 海报、宣传渠道、奖品、直播间和赛后成果材料。
- 实时比赛数据、选手表现和游戏内数据。
- 与本次改期无关的自由文本档案。

## 4. 最低数据质量规则

| 规则 | 不满足时的处理 |
|---|---|
| 比赛 ID 必须存在且处于可调整状态 | 拒绝进入排程并提示负责人 |
| 双方约赛时间必须包含日期和开始时间并使用统一时区；结束时间由 BO 类型计算 | AI 追问或要求人工确认 |
| 两队必须确认同一候选时间 | 维持“待确认”，不得提交正式审批 |
| 整个比赛时段内的已占用场次加本场不能超过裁判容量 | 候选时间判定为不可行 |
| 修改必须基于当前有效版本 | 要求刷新后重新计算，防止覆盖新变更 |
| 自然语言解析存在歧义 | 展示原文、结构化结果和疑点，由人确认 |

## 5. 负责人确认项

| 编号 | 决策 | 当前建议 | 负责人结论 |
|---|---|---|---|
| I1 | 时间输入最小粒度 | 不设置固定 15 分钟档位；直接记录双方约定的开始时间，并按 BO 类型计算结束时间 | 负责人于 2026-08-16 修订确认 |
| I2 | 队伍如何提交时间 | 两队先协商一个共同认可的约赛时间，再提交系统校验；首轮不填完整可用时间表 | 负责人于 2026-08-16 修订确认 |
| I3 | 谁负责提交队伍时间 | 每队仅由队长提交或确认，避免 160 名选手同时进入流程 | 确认采用（2026-08-16） |
| I4 | 裁判数据按人数还是个人记录 | 首轮只记录每个时段可支持的最大并发场次数，不记录个人裁判日历 | 负责人于 2026-08-16 修订确认 |
| I5 | 尚未产生参赛方的后续比赛如何表示 | 使用“比赛 X 胜者/败者”占位符，结果产生后自动绑定队伍 | 确认采用（2026-08-16） |
| I6 | AI 解析的自然语言能否直接生效 | 不能；必须由提交人或负责人确认结构化结果 | 确认采用（2026-08-16） |

### 5.1 简化后的最低输入

一次改期只需提交：比赛 ID、双方约定的新开始时间、改期原因和两队确认状态。系统从现有赛程取得 BO 类型与时长，并检查比赛依赖、冻结状态、阶段截止时间和裁判并发容量。

如果不保留“该时段最大并发场次”这一项，系统将无法避免上一届的 3 场同时进行事故，因此它是简化后仍必须存在的最低约束。
