### 本轮实测中发现并当场修复

1. 申请发起方曾被错误显示成审批方；现已区分“等待你处理 / 等待对方处理”，仅有权限者显示同意、拒绝。
2. 队长审批卡片最初看不到申请人；现仅向关联队长返回申请人游戏 ID，不公开姓名、学号和联系方式。
3. 退出玩家身份后残留上一操作成功提示；现已同步清空本地提示和编辑草稿。
4. 报名成功文案仍指向已取消的人才市场；已改为“创建队伍 / 申请已有队伍 / 精确游戏 ID 邀请”。
5. 报名期赛事曾错误显示“赛事回顾”；后续复核发现该页面实际是负责人填写亮点并生成战报的早期原型，不属于玩家侧功能，现已删除玩家入口与整个公开路由。最终赛果继续在赛事赛程和对阵中展示。
6. 手机端赛事按钮被挤成多行、邀请按钮过薄；已改为手机端整行操作并补足点击高度。

## 1. 实际走过的任务链

### 赛事负责人

登录工作台 → 新建“4 队单败 BO1”赛事 → 填写策划案 → 打开新赛事报名管理 → 打开赛程 → 打开抽签。

### 玩家

进入选手报名页 → 填写身份与联系方式 → 提交报名 → 进入人才市场 → 创建队伍；随后以 3 个独立浏览器会话并发提交报名。

本轮没有继续伪造“完成比赛”的结果。因为建赛、报名和赛程三段的数据已经出现阻断性错误，继续点击旧演示赛程不能证明真实闭环成立。

## 6. AI 接入前的四个验收 Gate

### Gate A：真实数据闭环

- 创建 4 队单败 BO1 后，自动产生 3 场空对阵骨架，不出现任何演示队伍。
- 建赛选择的阶段、队伍数和 BO 类型与抽签、赛程、公开页完全一致。
- 至少 20 个并发报名请求全部持久化，不能丢记录、覆盖或返回假成功。
- 队伍完成并经负责人确认后才能进入抽签；不完整或未确认队伍被明确拦截。
- 抽签 → 排期 → BP → 报分 → 晋级 → 决赛完成后，负责人端和玩家端读取同一份结果。

### Gate B：玩家移动端体验

- 390×844 视口无裁切、无横向溢出，导航不遮挡核心内容。
- 每个赛事阶段只突出一个当前主任务，同时保留次要信息入口。
- 玩家能查看并更正自己的报名资料；能创建队伍、申请加入、处理邀请或退出。
- “我的赛事”能展示报名/队伍状态、下一场比赛、比赛时间、对手和 BP 入口。
- 联系方式和入队操作满足最小隐私与同意要求。

### Gate C：赛事负责人工作台

- 赛事列表、新建比赛和单赛事工作区上下文明确，不显示错误赛事。
- 工作台不再复用玩家官网的大页脚和无关导航，核心画布优先。
- 当前阶段、阻塞原因、下一步操作和发布状态可在一屏内判断。
- 对阵图能表达轮次和晋级关系，并在常见桌面宽度下有效利用空间。
- 报名修改、审核、退赛/换人、名单锁定、抽签、排期、改期、报分都有可恢复的状态记录。

### Gate D：负责人亲自验收

- 彭杰亲自创建一场小型验收赛并完成负责人全流程。
- 至少使用两个独立玩家身份完成报名、组队、查看赛程和 BP。
- 记录每个任务的耗时、犹豫点、错误和需要回到群聊/文档补做的步骤。
- P0 阻断问题为 0，负责人明确确认玩家侧和工作台达到可接受水平后，才允许进入 AI Gate。
