### 2.2 分层：只落地了第一段

目标是 `app → components → hooks → domains → application → data-store`。实测结果：

| 规则 | 结论 |
|---|---|
| UI → domains（允许） | ✅ 成立 |
| domains → UI（禁止） | ✅ 0 例（这是重构做对的地方） |
| hooks 迁出领域层 | ✅ 5 个文件已在 `src/hooks/`，`lib` 内 hooks = 0 |
| domains → 基础设施（禁止） | ❌ 2 例（`result/reporting-data.ts`、`result/evidence-store.ts` 直连 data-store / data-backend） |
| 跨域只允许在 application | ❌ `result/reporting-data.ts` 反向依赖 schedule 域 5 个模块 |
| 写操作经 application 用例 | ❌ **2/35** 条路由经过 application；15 条路由直连 data-store |
| 界面层不直连数据访问 | ❌ 22 个文件仍在基线里（被冻结，不再新增但不减少） |

**一句话**：允许的依赖方向守住了，禁止的方向没有执行，而禁止项被写进了基线台帐 —— 守卫因此合法化了它们。

`19-平台架构重构方案` 的目标是 **7 个领域 + 四件套 + L0 内核**。实际：

### 2.4 赛制体系正在裂成两套，且最新功能「能存不能抽」

这是本次审视里**唯一一个「用户能点到、但结果是错」的功能性缺陷**：

1. **两套 `StageType` 联合**：`format-templates.ts` 5 种 vs `stage-chain-rules.ts` 6 种（互不包含）；类型→文案/白名单至少 **6 处**各自维护。
2. **同一个类型三个名字**：编辑器用 `group-single-elim`、持久化用 `single-elim-groups`、保存接口白名单里有前者没后者。
3. **服务端静默丢段**：保存接口 `api/admin/events/format/route.ts` 用 `.filter()` 过滤不在白名单的类型 —— 用户选「组内循环」保存会**返回成功但少一段**。
4. **服务端不校验**：`validateStageChain` 只在编辑器与测试里调用，保存路径完全没有；对比新建赛事路径是有 `resolveSupportedFormat` 调用的。
5. **抽签端只认 5 种固定结构**：`swiss.ts` / `round-robin.ts` 两个引擎全仓**只被自己的测试 import**，零生产调用点。
6. **编辑器自带模板有 3 个不可发布**：5 个预设里「16 队·瑞士轮+单败」「32 队·小组+双败」「36 队·四段（现行）」都会落到 unsupported。

结论：`e68ce13`（今天最后一个提交）自述「未在真浏览器验过」，而这个提交接的正是**写路径**。

### 2.5 守卫体系：有效，但有三类盲区

现有 3 条源码守卫（`arch` / `ui` / `color`）+ 1 条变异检查 + 1 条生产巡检，共 974 行，其中真正的判据只有约 90 行 —— 其余是三方各抄一遍的骨架（`walk()` 三份、`check()` 三份、基线读写三份）。`26-守卫与巡检梳理` 已经把这件事写清楚并给了方案，**但一条都没执行**。

盲区：

1. **方向只查「UI→内核」一条**，不查 domain→infra、domain↔domain；
2. **基线按路径只减不增**，同一文件可以无限增长（`FormatDrawWorkspace.tsx` 从基线 948 行涨到 975 行仍绿）；
3. **只 walk `.ts/.tsx`** → 1,965 行的 `globals.css` 永远不受行数规则约束。

另有一处**基线本身已过期**：`arch-baseline.json` 记录 20 个 >400 行文件，本次实测实际为 **17 个** —— `events/[id]/manage/page.tsx`(365)、`ReviewWorkspace.tsx`(393)、`tools/gate6/production-audit.ts`(387) 都已降到阈值以下，但基线没重生成，于是文档里「超限 20 个」这个数字一直在漂。

### 2.6 数据层：签名一致，语义不一致

| 维度 | file 后端 | Supabase 后端 |
|---|---|---|
| `read` 失败 | **任何**异常（含 JSON 损坏）静默返回 fallback | 仅「行不存在」返回 fallback，其余抛错/重试 |
| 并发 | 进程内锁（读也加写锁），单进程假设 | 无进程锁，CAS + 40 次重试 |
