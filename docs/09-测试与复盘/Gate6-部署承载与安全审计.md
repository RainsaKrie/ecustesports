## 2. 承载判断

首轮按 160 名选手、32 支队伍、3—4 名裁判和少量赛事负责人估算。这个规模本身不属于高并发业务，普通单体应用可以承载；当前主要风险不是页面访问量，而是本地文件存储、并发写入、公开接口滥用和故障后的数据恢复。

本地开发环境公开赛程读取冒烟结果：

| 项目 | 结果 |
|---|---:|
| 总请求 | 500 |
| 并发数 | 50 |
| 成功率 | 500 / 500 |
| P50 | 555 ms |
| P95 | 607 ms |
| 最大值 | 636 ms |
| 公开赛程响应体 | 21,811 bytes |
| 公开报名名单响应体 | 29,990 bytes |

该结果只能证明本机开发模式下公开读取没有立即失效，不能证明公网、代理、数据库、上传和并发写入在生产环境可靠。

## 4. Gate 6 阻塞项

| 编号 | 级别 | 当前事实 | Gate 6 要求 |
|---|---|---|---|
| G6-01 | P0 | 数据保存在项目目录 JSON，图片写入 `public/uploads` | 迁移到持久数据库和对象存储；或明确采用单机持久卷并完成备份恢复演练 |
| G6-02 | P0 | 文件锁只存在于单个 Node 进程；部分 BP 操作仍会读取后整文件覆盖 | 关键写操作使用数据库事务、版本号或乐观锁，并验证并发提交 |
| G6-03 | P0 | 未设置环境变量时使用内置管理员密码和签名密钥 | 生产启动强制要求独立高强度密钥和密码，不允许默认值 |
| G6-04 | P0 | 登录、报名、组队、约赛和 BP 接口没有速率限制 | 对登录和公开写接口分别限流，连续失败触发冷却 |
| G6-05 | P0 | 尚无自动备份、恢复步骤和恢复演练 | 建立自动备份，并在预发布环境完成一次恢复演练 |
| G6-06 | P1 | 未配置 CSP、HSTS、防嵌入、防 MIME 嗅探等安全响应头 | 在 HTTPS 域名配置并验证安全响应头 |
| G6-07 | P1 | Cookie 写接口没有显式 Origin/CSRF 校验 | 管理员状态变更接口校验同源请求或加入 CSRF 令牌 |
| G6-08 | P1 | 上传只校验浏览器声明的 MIME 和 5 MB 大小 | 校验真实文件签名、限制频率并迁移对象存储 |
| G6-09 | P1 | 共享管理员账号无法区分具体操作人 | 首轮至少使用强密码、定期轮换和关键操作日志；扩大使用前改为独立账号 |
| G6-10 | P1 | 没有健康检查、错误监控、容量指标和告警 | 建立可用性、错误率、接口延迟和容量告警 |
| G6-11 | P1 | 没有真实部署环境的读写压测 | 在预发布域名完成读取、写入和持续轮询测试 |
| G6-12 | P1 | 生产依赖审计报告 `nanoid@3.3.17` 存在 1 个高等级间接依赖告警 | 升级到修复版本或记录不可利用性证据，重新审计 |

## 5. 建议部署形态

首轮不需要为互联网大规模访问设计微服务。建议采用：

1. 单个 Next.js 应用实例，保留当前产品结构。
2. 托管 PostgreSQL 保存赛事、报名、队伍、赛程、BP 和操作记录。
3. 对象存储保存赛事主视觉，不写应用目录。
4. HTTPS 域名前使用具有限流和基础防护能力的反向代理或托管平台。
5. 预发布环境与正式环境分离；正式环境只使用环境变量中的密钥。

若为了快速试用选择单机持久卷，只能作为受控内测方案，且仍必须完成备份恢复、限流和安全配置。

## 6. Gate 6 放行测试

### 承载测试

| 场景 | 目标负载 | 通过标准 |
|---|---:|---|
| 集中查看赛事页、名单和赛程 | 300 个并发读取用户 | 5xx 低于 1%，P95 小于 1 秒 |
| 报名截止前集中提交或修改 | 30 个并发写请求 | 不丢失、不重复、不覆盖其他玩家数据 |
| BP 与比赛状态持续读取 | 100 个客户端持续 10 分钟 | 服务稳定，无延迟累积和数据回退 |
| 负责人操作与玩家操作同时发生 | 10 个管理/玩家写请求并发 | 数据一致，冲突返回明确结果，不出现静默覆盖 |

以上阈值只用于校园首轮验收，不代表商业化容量承诺。

### 安全与恢复测试

- 生产环境缺少管理员密码或签名密钥时拒绝启动。
- 未登录用户不能读取完整报名资料，也不能调用负责人写操作。
- 普通选手不能操作其他选手、其他队伍或非本队比赛；非队长不能约赛或操作 BP。
- 登录暴力尝试、重复报名和高频接口调用会被限制并留下记录。
- 管理员会话仅通过 HTTPS 传输，登出和密钥轮换后旧会话失效。
- 上传伪装文件、超大文件和高频上传被拒绝。
- 数据库与图片完成备份，并能在空白预发布环境恢复到一致赛事状态。
- 依赖审计不存在未处理的高危或严重漏洞。
- 服务异常、写入失败和容量接近上限时能够产生告警。
