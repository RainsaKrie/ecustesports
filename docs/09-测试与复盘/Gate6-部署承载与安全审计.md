# Gate 6：部署承载与安全审计

- 审计日期：2026-08-30
- 审计对象：MVP 3.77 与 Vercel / Supabase 预发布环境
- 当前结论：Gate 5、Gate 6 已通过；校内三种网络、备份值守与外部告警降级为正式办赛前检查，不再阻塞当前作品集项目推进
- 审计范围：公网部署、校园赛事规模承载、数据持久化、账号与接口安全、备份恢复和运行监控
- 审计限制：本次包含代码审计、Vercel 预发布压测与 Supabase staging 演练，但不等同于渗透测试，也不能代替华理校园网、宿舍网和移动网络实测

## 1. Gate 决定

负责人确认现有功能闭环满足 Gate 5。剩余 UI 与布局问题进入非阻塞优化清单，不再阻止部署准备。

Gate 6 独立评审，只有部署承载和安全风险获得真实证据后才允许进入 Gate 7 真实赛事试用。AI 接入继续暂停，当前阶段不增加 AI 功能。

## 2. 承载判断

首轮按 160 名选手、32 支队伍、3—4 名裁判和少量赛事负责人估算。这个规模本身不属于高并发业务，普通单体应用可以承载；当前主要风险不是页面访问量，而是本地文件存储、并发写入、公开接口滥用和故障后的数据恢复。

本地开发环境公开赛程读取冒烟结果：

| 项目 | 结果 |
|---|---:|
| 总请求 | 500 |
| 并发数 | 50 |
| 成功率 | 500 / 500 |
| P50 | 555 ms |
| P95 | 607 ms |
| 最大值 | 636 ms |
| 公开赛程响应体 | 21,811 bytes |
| 公开报名名单响应体 | 29,990 bytes |

该结果只能证明本机开发模式下公开读取没有立即失效，不能证明公网、代理、数据库、上传和并发写入在生产环境可靠。

## 4. Gate 6 初始阻塞项

| 编号 | 级别 | 当前事实 | Gate 6 要求 |

### 当前 Gate 判断

应用和数据层已经具备 160 人校内赛预发布试用能力，且没有证据表明正常校园赛事访问会导致服务失效。但不能把结果扩大解释为“300 人同一毫秒进入仍满足 P95 < 1 秒”：该严格指标未通过，必须原样保留。

负责人于 2026-08-30 确认以下检查不是当前作品集与预发布阶段的必要门槛，Gate 6 据此通过。2026-09-01 进一步决定先完成公开部署上线，AI 接入和离线 B 方案均继续暂停。

以下事项降级为正式承载真实赛事前的上线检查：

1. 用华理校园网、宿舍网、移动网络分别打开首页、赛程、参赛中心并完成一次写操作；
2. 明确赛事期间的手工备份节点与执行人，并把最近备份保存在不进入 Git 的受控目录；
3. 为 `/api/health` 建立站外可用性监控或明确人工巡检班次；
4. 正式域名只在上述三项通过后绑定，初次上线保持报名关闭。

本轮本地回归证据：TypeScript、全量 ESLint、生产构建、20/20 规则、100/100 完整闭环、44/44 BP、9/9 报名运营、7/7 发布、16/16 阶段引导全部通过；`/api/health` 返回 200，首页与健康接口均带 CSP、`nosniff` 和 `DENY`，已登录调用旧报名整份写入口返回 405；匿名迁移预检为 5 个文档、约 1.45 MB；生产依赖审计为 0 个漏洞。

## 5. 建议部署形态

首轮不需要为互联网大规模访问设计微服务。建议采用：

1. 单个 Next.js 应用实例，保留当前产品结构。
2. 托管 PostgreSQL 保存赛事、报名、队伍、赛程、BP 和操作记录。
3. 对象存储保存赛事主视觉，不写应用目录。
4. HTTPS 域名前使用具有限流和基础防护能力的反向代理或托管平台。
5. 预发布环境与正式环境分离；正式环境只使用环境变量中的密钥。

若为了快速试用选择单机持久卷，只能作为受控内测方案，且仍必须完成备份恢复、限流和安全配置。

## 6. Gate 6 放行测试

### 承载测试

| 场景 | 目标负载 | 通过标准 |
|---|---:|---|
| 集中查看赛事页、名单和赛程 | 300 个并发读取用户 | 5xx 低于 1%，P95 小于 1 秒 |
| 报名截止前集中提交或修改 | 30 个并发写请求 | 不丢失、不重复、不覆盖其他玩家数据 |
| BP 与比赛状态持续读取 | 100 个客户端持续 10 分钟 | 服务稳定，无延迟累积和数据回退 |
| 负责人操作与玩家操作同时发生 | 10 个管理/玩家写请求并发 | 数据一致，冲突返回明确结果，不出现静默覆盖 |

以上阈值只用于校园首轮验收，不代表商业化容量承诺。

### 安全与恢复测试

- 生产环境缺少管理员密码或签名密钥时拒绝启动。
- 未登录用户不能读取完整报名资料，也不能调用负责人写操作。
- 普通选手不能操作其他选手、其他队伍或非本队比赛；非队长不能约赛或操作 BP。
- 登录暴力尝试、重复报名和高频接口调用会被限制并留下记录。
- 管理员会话仅通过 HTTPS 传输，登出和密钥轮换后旧会话失效。
- 上传伪装文件、超大文件和高频上传被拒绝。
- 数据库与图片完成备份，并能在空白预发布环境恢复到一致赛事状态。
- 依赖审计不存在未处理的高危或严重漏洞。
- 服务异常、写入失败和容量接近上限时能够产生告警。
